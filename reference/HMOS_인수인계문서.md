## 2. 오늘 설계한 이론 — HMOS 언어 인식 엔진

### 핵심 원리
수학 기호는 계산 도구가 아닙니다.  
**일반 언어 구조가 품고 있는 수학적 실체의 압축**입니다.

"~일 때, ~인" 이라는 언어가 먼저 존재하고,  
그 실체가 P(B|A)로 매핑됩니다.  
기호는 언어의 실체를 여는 열쇠입니다.

### 세 층위 구조
```
1층 — 숲을 보는 층 (질문 인식)     ← 문법7
2층 — 급소를 여는 층 (실체 인식)   ← 기호26
3층 — 흐름을 읽는 층 (채점)        ← HMOS 7문법 + 원자단위
```

### 층위 간 관계
```
기호26 + 문법7 (원천 원리)
        ↓
   7문법 형식 조합 (D·Q·B·P·C·L)
        ↓
   원자단위 분해·채점 (개념·조건·논리·연산)
```

### AI 읽기 순서 (엔진 작동 방식)
```
문제 입력
    ↓
문법7 → 질문 방향 식별 (숲, 전체)
    ↓
기호26 → 언어를 기호로 매핑 → 실체 확인 (급소)
    ↓
HMOS 7문법 → 답안 흐름 채점 (나무)
    ↓
원자단위 → 국소 피드백 출력 (잎)
```

## 3. 오늘 확보한 자료 2개

### 자료1 — 수학기호26
- 위치: 이미지 2장 (사진 촬영본)
- 구성: 사고의 흐름 / 핵심 유도등 / 연산자 호출 규격 / 매트릭스 코드 / 수학 기호 / 언어 조사
- 범위: 확률·통계·기하 영역 + 해석·대수 영역
- 변환 예정: `reference/symbol-map-26.json`

### 자료2 — 수학의 7가지 문법
- 위치: hmos-grader 폴더 안 워드 파일 (원서)
- 구성: 7가지 문법 패턴
  - 단문 독해: "…의 값은?" → 존재 확인
  - 제한 독해: "~일 때, …의 값은?" → 상황 속 대상
  - 형상 독해: "f(x) 그래프 위의 ~같이는?" → 그림과 식 연결
  - 맥락 독해: "~에 대하여, ~의 값은?" → 대상 소환
  - 본질 독해: "~가 되도록 하는 …의 값은?" → 역추적 명령
  - 질서 발견: "~일 때, ~의 값은?"
  - 인과 매듭: "…의 과정이다. [ ]의 값은?"
- 변환 예정: `reference/grammar-7.json`

## 6. ENGINE_SPEC.md 내용 (붙여넣기용)

```
# HMOS 언어 인식 엔진 명세서

## 핵심 원리
수학 기호는 일반 언어 구조가 품고 있는 수학적 실체의 압축이다.
기호26과 문법7은 참조자료가 아닌 읽기 원리로 작동한다.

## 읽기 순서
1. 문법7 → 질문 방향 식별 (숲, 전체를 위에서 내려다봄)
2. 기호26 → 언어를 기호로 매핑 → 실체 확인 (급소)
3. HMOS 7문법 → 답안 흐름 채점
4. 원자단위 → 국소 피드백 출력

## 채점 원칙
- 문장의 표면이 아닌 기호가 여는 수학적 실체로 판단한다
- 학생 답안의 언어 표현이 해당 기호의 실체와 일치하는가를 본다
- 틀렸다/맞다가 아닌 어느 층위에서 막혔는가를 출력한다

## 참조 파일
- reference/symbol-map-26.json
- reference/grammar-7.json
```

## 7. 주요 개념 정리

**기호26** — 언어 구조를 수학 기호로 매핑한 표. 문장 속 언어 조사·어미 패턴이 어떤 수학적 실체를 품고 있는지를 연결한다. AI가 문장을 읽는 배경 원리로 작동해야 한다.

**문법7** — 문제 문장 끝 패턴으로 질문이 무엇을 요구하는지 방향을 잡는 도구. 숲을 먼저 보는 층. 인간 고수의 직감에 해당한다.

**HMOS 7문법** — 기호26 + 문법7의 조합으로 만들어진 형식 (D·Q·B·P·C·L). 뿌리에서 나온 형식이다.

**원자단위** — 개념·조건·논리·연산. 실제 채점의 국소화 도구.

**워크스페이스 키** — `sk-ant-usr-1_`로 시작. API 호출 시 반드시 `anthropic-workspace-id` 헤더 포함 필요.
