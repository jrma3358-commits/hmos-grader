## 전체 구조

```
                    ┌─────────────────┐
                    │  f(Q) ENGINE    │
                    │  질문 인식 엔진  │  ← ENGINE_SPEC.md
                    │  M, C, R, K, T  │     먼저 만든다
                    └────────┬────────┘
                             │
          ┌──────────────────┼──────────────────┐
          │                  │                  │
          ▼                  ▼                  ▼
  ┌───────────────┐  ┌──────────────┐  ┌───────────────┐
  │ 문제 설계 검증 │  │  유형별 인식  │  │   손글씨 인식  │
  │               │  │              │  │               │
  │ QUESTION_     │  │ QUESTION_    │  │ IMAGE_        │
  │ DESIGN_SPEC   │  │ TYPE_SPEC    │  │ RECOGNITION_  │
  └───────┬───────┘  └──────┬───────┘  │ SPEC          │
          │                  │          └───────┬───────┘
          │                  │                  │
          └──────────────────┼──────────────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │   채점기         │
                    │                 │
                    │   CLAUDE.md     │
                    │   PHASE A/B/C   │
                    └─────────────────┘
                             │
                             ▼
                    [교사 최종 확정]
```

---

## 파일별 역할

| 파일 | 역할 | 엔진과의 관계 |
|------|------|-------------|
| `ENGINE_SPEC.md` | f(Q) 엔진 — 질문 인식 | **심장** — 먼저 개발 |
| `QUESTION_DESIGN_SPEC.md` | 출제 단계 문제 검증 | 엔진의 weight_center 사용 |
| `QUESTION_TYPE_SPEC.md` | 유형별 f(Q) 분기 규칙 | 엔진의 detected_type 사용 |
| `IMAGE_RECOGNITION_SPEC.md` | 손글씨 3패스 인식 | 엔진의 K·T를 PASS 3에 주입 |
| `CLAUDE.md` | 채점기 전체 로직·철학 | 엔진 출력이 PHASE A 완료 |

## 데이터 흐름

```
[출제자] 제시문·자료 설계
    │
    ▼
[QUESTION_DESIGN_SPEC]
    제시문 → f(Q) 엔진 → 무게중심 추출
    주문제 + 대안문제 설계 → 비교 검토
    문제 확정
    │
    ▼
[f(Q) ENGINE] ← 핵심 실행
    질문 Q 입력
    ↓
    M, C, R, K, T 추출
    ↓
    유형 판별 (TYPE 1/2/3)
    ↓
    루브릭 4축 도출
    ↓
    하위 모듈 컨텍스트 생성
    │
    ├──────────────────────┐
    │                      │
    ▼                      ▼
[QUESTION_TYPE_SPEC]   [IMAGE_RECOGNITION_SPEC]
    유형별 분기           PASS 1: 이미지 직독
    배점 비중 적용        PASS 2: 문법 맥락 복원
                          PASS 3: K·T로 필터
                          신뢰도 판정 (0.85 기준)
    │                      │
    └──────────┬───────────┘
               │
               ▼
          [CLAUDE.md]
          PHASE A: 루브릭 패키지 완성
          PHASE B: 학생 답안 루브릭 대조
          PHASE C: 결과표 생성
               │
               ▼
          [교사 최종 확정]
          가치 배분 + 채점 확정
```

## 개발 순서

```
STEP 1 ── ENGINE_SPEC.md 구현
           f(Q) 엔진 완성
           검증 테스트 통과
           │
           ▼
STEP 2 ── CLAUDE.md PHASE A 연결
           엔진 출력 → 루브릭 패키지
           │
           ▼
STEP 3 ── QUESTION_TYPE_SPEC 연결
           유형별 분기 + 배점 비중
           │
           ▼
STEP 4 ── CLAUDE.md PHASE B 구현
           학생 답안 채점 실행
           │
           ▼
STEP 5 ── IMAGE_RECOGNITION_SPEC 연결
           손글씨 → 텍스트 → PHASE B
           │
           ▼
STEP 6 ── CLAUDE.md PHASE C 구현
           결과표 생성
           │
           ▼
STEP 7 ── QUESTION_DESIGN_SPEC 연결
           출제 검증 → 채점 전 게이트
```

## 철학

```
AI는 운전자, HMOS는 네비게이션
빛이 모든 곳에 닿게 한다
채점의 실체는 질문의 실체 인식에 있다

f(Q) 엔진이 그 인식이다
```

---

## 완성의 조건

```
□ f(Q) 엔진이 재현성 있게 작동하는가
□ 세 유형(TYPE 1/2/3) 모두 처리되는가
□ 손글씨가 3패스로 읽히는가
□ 창의적 풀이가 루브릭으로 인정되는가
□ 결과가 학생·교사·학부모에게 보이는가
□ 교사가 최종 확정하는 구조가 있는가
□ 문제 설계가 채점 전에 검증되는가

이 일곱 가지가 모두 충족될 때
빛이 모든 곳에 닿는 채점 시스템이 완성된다
```

## 이론 문서 — 스펙의 뿌리

### HMOS_논문5_오류복원_TSR-1.md

**TSR (Truncated Solution Restoration)**

오류 복원 루틴. PHASE B 피드백의 이론적 토대.

```
핵심 연결:

ENGINE_SPEC.md K(급소)
  = 논문5의 급소 (질문 의도가 응결된 지점)

CLAUDE.md PHASE B 오류 유형
  = 논문5의 절단 / 비약 / 정상 단축

PHASE B 피드백
  = 논문5의 TSR 순방향 재생성

지금 스펙 (POC):
  "어느 축에서 틀렸는가" → 오류 유형 분류

TSR 적용 후 (정식 버전):
  "어느 지점이 잘렸는가" → 위치 특정
  "급소에서 무엇을 채워야 하는가" → 재생성 제시
```

POC에서는 현재 스펙으로 충분.
정식 버전에서 PHASE B에 TSR 레이어 추가.

### 서술형채점_12_채점가이드_비개발자용.docx

**판정조건 가이드 — PHASE B 실행 규칙**

```
이 문서의 위치:
  ENGINE_SPEC.md  → 무엇을 추출할 것인가 (설계)
  CLAUDE.md       → 어떻게 채점할 것인가 (구조)
  이 문서         → 각 판정을 어떻게 내릴 것인가 (규칙)

핵심 연결:

섹션 4 맥락 복원 confidence 상/중/하
  → IMAGE_RECOGNITION_SPEC 신뢰도 기준 정교화

섹션 5 Q-B-C 구조
  → ENGINE_SPEC f(Q)에 B(대상) 독립축 추가 필요

섹션 7 인과 판정 (끊긴 지점 기록)
  → 논문5 TSR 실행 규칙

섹션 9~10 ok/partial/missing/needs_review
  → CLAUDE.md PHASE B ○/△/✗의 상세 판정 기준

섹션 3 hard_zero
  → 0점 조건 4가지 모두 충족해야만 0점

1차 구현에서:
  화면의 허용답안·오답조건 = 이 문서 섹션 3,4,5
  인정-보정 퍼센트 = 이 문서 섹션 9
```

### 서논술형_연재_12회_전편-2.md

**교사·학부모·정책 입안자 설득 언어 — 5부 12회 연재**
**저자: 오예원·오재원 / 훈민OS 평가솔루션연구소**

```
이 연재의 위치:
  논문       → 이론 (연구자용)
  기술백서   → 구현 (개발자용)
  스펙 6개   → 개발 (Claude Code용)
  이 연재    → 왜 필요한가 (교사·학부모용)

교사 시연 전 배포 문서로 활용 가능

핵심 연결:

4회 공정한 채점의 세 조건
  → HMOS 설계 세 원칙 (근거/경로/반박)
  → CLAUDE.md 핵심 명제와 동일

5회 채점의 얼굴 ①
  → alt_ 코드 체계 + needs_review
  → 도투마리 6.5점의 원리 예고

9회 세 사람의 상식
  → PHASE C 3인 결과표 (학생/교사/학부모)

10회 투명이 사교육을 이긴다
  → QUESTION_DESIGN_SPEC 출제 검증의 이유

12회 궤적의 주인은 누구인가
  → "AI가 최종 확정하면 안 되는 이유"
     대중 언어 버전
```
