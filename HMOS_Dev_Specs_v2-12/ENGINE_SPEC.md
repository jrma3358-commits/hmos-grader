## 핵심 원리 — 5색이 출제자의 시선이다

```
수학 문제는 인간 사유를 담은 가장 압축된 문장이다.
그 사유는 조사·어미를 통해 5색으로 드러난다.

출제자는 이 5색을 통해 설계 로직을 심어두었다.
f(Q)는 그 5색을 읽어 출제자의 의도를 복원한다.

"검은 글자"를 "살아있는 그림"으로 바꾸는 것
— 그것이 f(Q)의 실체다.
```

## 1. 5색 정의 — f(Q)의 입력 분해

```
● 초록  B (대상·배경)
  조사: ~이/가, ~에 대하여, ~을/를
  역할: 배경 지식과 단원 소환 스위치
        막연한 문제를 "내가 아는 영역"으로 끌어들임
  예:  "함수 f(x)가", "수열 {an}에 대하여"

● 파랑  C (제약·조건)
  조사: ~일 때, ~가 되도록, ~이면, 단 ~
  역할: 무한한 가능성을 깎아내는 날카로운 칼날
        출제자가 원하는 머릿속 단 하나의 순간을 포착
  예:  "0 < a < 12일 때", "연속이 되도록"

● 보라  P (상황·시각)
  조사: 그림과 같이 ~, ~이고, ~가 있다
  역할: 시각 정보(그림·표·그래프)와 텍스트를 연결하는 다리
        복잡한 그림을 조목조목 분해하여 인지하게 함
  예:  "그래프는 직선구간을 운동하는 물체의 속도를 나타낸다"

● 노랑  D (정의·새 규칙)
  조사: ~라 할 때, ~라 하자, ~로 정의한다
  역할: 이 문제에서만 적용되는 새 규칙과 함수를 받아들이는 통로
        "이 판에서는 이렇게 놀자"는 약속
  예:  "g(x) = { 2x+5a (x≥a) / f(x+4) (x<a) }라 할 때"

● 빨강  Q (질문·목적지)
  조사: ~의 값?, ~을 구하여라, ~을 서술하시오
  역할: 모든 사고가 수렴해야 할 최종 목적지
        "무엇을 구할 것인가"의 본질을 놓치지 않게 하는 신호
  예:  "a값의 범위를 구하고, 모든 실수 a값을 구하는 과정을 쓰시오"
```

## 2. f(Q) 함수 — 완전판

```
f(Q) = 5색 읽기 + 급소 추출

STEP 1 — 5색 읽기 (출제자의 시선 복원)
  조사·어미를 기준으로 5색을 분리 추출
  B(초록) → C(파랑) → P(보라) → D(노랑) → Q(빨강)

STEP 2 — 급소 추출 (채점 진단)
  K(급소): 5색 중 어느 하나가 이후 전체를 가름

STEP 3 — 루브릭 5축 도출 (자동)
  B → 축1 (대상): 주인공 개념을 제대로 잡았는가
  C → 축2 (조건): 제약을 빠짐없이 분류했는가
  P → 축3 (상황): 시각 정보를 논리에 연결했는가
  D → 축4 (정의): 새 규칙을 문제에 적용했는가
  Q → 축5 (결론): 최종 목적지에 도달했는가

STEP 4 — 모범답안 추출 (루브릭 검증)
  모범답안은 5색을 순서대로 통과한 궤적
  B 소환 → D 수용 → C 분류 → P 연결 → Q 도달
```

## 3. 데이터 스키마 — 완전판

```typescript
// 5색 추출 결과
interface FiveColors {
  B: string;      // 초록: 대상·배경
  C: string;      // 파랑: 제약·조건
  P?: string;     // 보라: 상황·시각 (선택 — 없는 문제도 있음)
  D?: string;     // 노랑: 정의·새규칙 (선택)
  Q: string;      // 빨강: 질문·목적지
  Q_verb: string; // 요구 동사 (구하시오/서술하시오/논하시오...)
}

// 급소와 함정
interface KT {
  K: string;                // 급소 — 반드시 하나
  K_color: "B"|"C"|"P"|"D"; // 어느 색에서 급소가 나왔는가
  K_is_single: boolean;
}

// 루브릭 5축
interface RubricAxis {
  axis_id: 1|2|3|4|5;
  axis_color: "B"|"C"|"P"|"D"|"Q";
  axis_name: "대상"|"조건"|"상황"|"정의"|"결론";
  criteria: string;           // 판정 기준
  score: number;              // 배점
  is_active: boolean;         // P, D가 없는 문제는 비활성
}

// 모범답안 궤적
interface ModelAnswerPath {
  path_id: string;
  description: string;
  // 5색 순서대로 통과 여부
  traversal: {
    B: { passed: boolean; evidence: string };
    D: { passed: boolean; evidence: string };
    C: { passed: boolean; evidence: string };
    P: { passed: boolean; evidence: string };
    Q: { passed: boolean; evidence: string };
  };
  is_primary: boolean;        // 주경로 vs alt경로
}

// 엔진 최종 출력
interface EngineOutput {
  detected_type: DetectedType;
  five_colors: FiveColors;
  kt: KT;
  rubric: RubricAxis[];
  model_paths: ModelAnswerPath[];  // 주경로 + alt경로들
  weight_center: string;           // QUESTION_DESIGN_SPEC용
  recognition_context: string[];   // IMAGE_RECOGNITION_SPEC용
}

## 4. 시스템 프롬프트 — 5색 기반 완전판

```
SYSTEM:
당신은 HMOS f(Q) 엔진입니다.
출제자의 시선으로 질문을 읽는 것이 유일한 임무입니다.

[5색 읽기 원칙]
한글의 조사·어미는 출제자 사유의 논리 스위치입니다.
색마다 고유한 조사·어미 패턴이 있습니다.

● 초록(B) 대상: ~이/가, ~에 대하여, ~을/를
  → 배경 지식과 단원을 소환합니다
  → 이 문제가 어떤 개념 영역인지 확정합니다

● 파랑(C) 조건: ~일 때, ~가 되도록, 단 ~, ~이면
  → 무한한 가능성 중 출제자가 원하는 하나를 좁힙니다
  → 조건이 여럿이면 모두 추출합니다 (누락 금지)

● 보라(P) 상황: 그림과 같이, ~이고, ~가 있다
  → 그래프·표·도형이 있을 때 활성화됩니다
  → 시각 정보와 텍스트의 연결 지점을 포착합니다
  → 없는 문제는 P = null

● 노랑(D) 정의: ~라 할 때, ~라 하자, ~로 정의
  → 이 문제에서만 통용되는 새 규칙입니다
  → "이 판에서는 이렇게 놀자"는 약속을 받아들입니다
  → 없는 문제는 D = null

● 빨강(Q) 질문: ~의 값?, ~을 구하여라, ~을 서술하시오
  → 모든 사고가 수렴해야 할 최종 목적지입니다
  → Q를 놓치면 아무리 잘 풀어도 0점입니다

[급소(K) 추출 원칙]
5색을 모두 추출한 뒤 물어봅니다:
"이 5색 중 어느 하나를 놓치면 이후 전체가 무너지는가?"

K는 반드시 하나입니다.
K가 여럿이면 문제 설계 오류입니다 (design_warning 출력).

K가 어느 색에서 나왔는지(K_color)를 명시합니다:
  C(파랑)에서 자주 나옴: 핵심 조건 인식
  D(노랑)에서 자주 나옴: 새 정의 적용
  B(초록)에서 나옴: 단원·개념 오인

[루브릭 도출 원칙]
5색 → 5축 매핑은 기계적입니다:
  B → 축1 (대상이 맞는가)
  C → 축2 (조건이 완전한가)
  P → 축3 (시각 정보가 연결됐는가, P=null이면 비활성)
  D → 축4 (새 규칙이 적용됐는가, D=null이면 비활성)
  Q → 축5 (결론이 목적지에 도달했는가)

배점 비중은 유형별로 다릅니다:
  TYPE 1 수학: 축2(C)+축5(Q) 무거움
  TYPE 2 논술: 축1(B)+축2(C) 무거움, 축3(P)·축4(D) 없음
  TYPE 3 자료: 축3(P)+축5(Q) 무거움 — 보라가 핵심

[모범답안 추출 원칙]
모범답안은 5색을 순서대로 통과한 궤적입니다:
  B(대상 소환) → D(정의 수용) → C(조건 분류) → P(시각 연결) → Q(결론 도달)

이 궤적을 통과하는 경로가 여럿이면 alt경로입니다.
alt경로도 같은 5색 궤적을 통과하면 만점입니다.

출력: EngineOutput JSON만 반환합니다.
```

## 5. 5색 → 루브릭 → 모범답안 흐름

```
[질문 입력]
      │
      ▼
5색 분리 추출
  B(초록): 대상 소환
  C(파랑): 조건 파악
  P(보라): 시각 연결 (있으면)
  D(노랑): 새 규칙 (있으면)
  Q(빨강): 최종 목적지
      │
      ▼

      │
      ▼

  B→축1 / C→축2 / P→축3 / D→축4 / Q→축5

      │
      ▼

  주경로: B→D→C→P→Q 순서로 통과
  alt경로: 같은 5색을 다른 방식으로 통과
      │
      ▼
검증
  ① 주경로가 루브릭 5축 통과하는가?
  ② 각 축이 실체(B·C·P·D·Q) 하나에 대응하는가?
  ③ alt경로가 같은 루브릭을 통과하는가?
      │
      ▼
[EngineOutput 출력]
```

## 6. 실례 — 수학 연속 함수 문제 (수학 채점 화면)

```
문제:
f(x) = x²-8x+a에 대하여
g(x) = { 2x+5a (x≥a) / f(x+4) (x<a) }를 만족시킬 때,
방정식 f(x)=0은 열린구간 (0,2)에서 적어도 하나의 실근을 갖는다.
f(x)g(x)는 x=a에서 연속이다.
a값의 범위를 구하고, 모든 실수 a값을 구하는 과정을 쓰시오.

5색 추출:
  B(초록): f(x) = x²-8x+a / 함수 g(x)
            → 이차함수와 연속함수 단원 소환

  D(노랑): g(x) = { 2x+5a (x≥a) / f(x+4) (x<a) }
            → 이 문제에서만 통용되는 함수 정의

  C(파랑): 방정식 f(x)=0이 (0,2)에서 실근을 가짐
            f(x)g(x)가 x=a에서 연속임
            → 두 가지 조건 동시 적용

  P(보라): null (그래프 없음)

  Q(빨강): a값의 범위 + 모든 실수 a값
            + 풀이 과정 서술
            → 범위와 개별 값 둘 다 요구

K(급소): D에서 — g(x)의 구간 정의를 x=a에서 연결해야 함
          "a가 분기점이며 연속 조건의 핵심"

아직 안 펴진 실체 (학생의 이해가 닿지 않은 자리):
  ① D 미적용: g(x) 정의를 무시하고 f(x)만 채점
     → 접힌 실체: D / folded_axis: 축4
  ② C 불완전: 두 조건 중 하나만 사용
     → 접힌 실체: C / folded_axis: 축2
  ③ Q 오인: 범위만 구하고 개별 값 미도출
     → missed_color: Q / axis_impact: 축5

루브릭:
  축1 대상B 20%: f(x), g(x) 모두 주인공으로 잡았는가
  축2 조건C 20%: 실근 조건 + 연속 조건 둘 다 적용했는가
  축3 상황P  0%: 비활성 (그래프 없음)
  축4 정의D 20%: g(x) 구간 정의를 x=a에서 연결했는가
  축5 결론Q 40%: 범위(0<a<12) + 개별값(a=7,8) 모두 도달했는가

모범답안 궤적:
  B: f(x)=x²-8x+a, g(x) 구간별 함수 인식
  D: g(x) 정의를 x=a 양쪽에 적용
  C: ① f(x)=0의 근이 (0,2)에 있음 → 0<a<12
      ② f(a)=0 또는 f(a+4)=7a → a=7,8
  P: (없음)
  Q: 범위 0<a<12, 값 a=7,8 도출

실제 채점화면과 비교:
  alt_condition  = 축2(C) 조건 적용
  alt_principle  = 축2(C) 실근 조건 원리
  alt_relation   = 축4(D) + 축2(C) 연속 관계
  alt_development = B+D+C 전개 과정
  alt_conclusion  = 축5(Q) 최종 결론
  → 5색이 alt_ 코드로 구현됐었음
```

## 7. 유형별 5색 활성화 패턴

```
TYPE 1 수학·과학 주관식:
  B ✓ C ✓ P △(있을 수도) D △(있을 수도) Q ✓
  K는 대부분 C(파랑)나 D(노랑)에서 나옴
  루브릭: 축2(C)+축5(Q) 무거움

TYPE 2 제시문 논술:
  B ✓ C ✓ P ✗ D ✗ Q ✓
  B(초록) = 제시문 핵심 개념·인물 소환
  C(파랑) = 포함 조건 체크리스트
  K는 B(초록)에서 나옴 (제시문 독해)
  루브릭: 축1(B)+축2(C) 무거움
  축3(P)·축4(D) 비활성

TYPE 3 자료 해석:
  B ✓ C ✓ P ✓✓ D △ Q ✓
  P(보라) = 그래프·표가 핵심
  K는 P(보라)에서 나옴 (자료 독해)
  루브릭: 축3(P)+축5(Q) 무거움
```

## 8. 채점가이드 Q-B-C와 5색 통합

```
채점가이드 12번 섹션5의 Q-B-C =
5색의 Q(빨강) + B(초록) + C(파랑)

판정 순서:
  B 확인: 주인공 개념을 제대로 잡았는가 → 축1
  C 확인: 조건을 모두 사용했는가       → 축2
  P 확인: 시각 정보와 연결했는가        → 축3
  D 확인: 새 규칙을 적용했는가          → 축4
  Q 확인: 최종 목적지에 도달했는가      → 축5

인과 판정 (TSR 연결):
  B→D→C→P→Q 순서로 궤적이 완결되어야 함
  어느 색에서 끊겼는가 = 절단(Truncation) 위치
  어느 색을 건너뛰었는가 = 비약(Leap) 위치
```

## 10. 개발 순서 — v3 기준

```
WEEK 1 Day 1: 5색 추출 구현
  입력: 질문 Q
  출력: FiveColors { B, C, P, D, Q, Q_verb }
