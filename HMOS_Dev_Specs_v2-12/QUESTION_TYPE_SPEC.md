## 이 문서의 위치

CLAUDE.md의 f(Q) 함수가 세 유형에 따라
어떻게 다르게 작동하는지를 정의한다.

f(Q)의 뼈대(M, C, R, K, T → 루브릭 4축)는 동일하다.
유형마다 **읽는 방식**과 **급소의 성격**이 달라진다.

```

    ├── TYPE 1: 수학·과학 주관식

    │
    ├── TYPE 2: 제시문 기반 논술

    │
    └── TYPE 3: 자료 해석 추론
               그래프·표·실험 결과
```

## 2. TYPE 1 — 수학·과학 주관식 (풀이 과정 서술)

### 2.1 이 유형의 핵심

```
질문이 묻는 것:
"이 학생이 풀이의 논리적 경로를 따라갔는가"

급소(K)의 성격:
→ 개념 인식 — 어떤 수학적 실체를 알아야 하는가
→ 조건 분류 — 경우를 빠짐없이 나눴는가
→ 경로 선택 — 올바른 풀이 경로를 선택했는가

모범답안의 성격:
→ 다경로 허용이 가장 강하게 적용됨
→ 같은 답이 나와도 경로가 없으면 감점
→ 풀이가 있어도 경로가 잘못됐으면 부분점수
```

### 2.2 f(Q) 작동 방식 — TYPE 1

```
M (재료) = 주어진 수, 조건, 도형, 수식
           → 중복 원소, 특수값, 제약 조건을 정밀하게 파악
           → "a가 2개" 같은 재료의 수학적 실체가 급소로 이어짐

C (조건) = "~할 때", "~이 되도록", "단 ~"
           → 경우 분류의 완전성이 핵심
           → 빠진 경우 없는가, 중복된 경우 없는가

R (요구) = "구하고 풀이 과정을 서술하시오"
           → 수치 + 경로 모두 요구
           → 수치만 맞으면 축4만 통과, 나머지는 감점

K (급소) = 재료에서 읽히는 핵심 수학적 인식 하나
           예: "a가 2개 → (a,a) 경우 존재"
               "소수 → 약수가 1과 자신뿐"
               "절댓값 → 부호 분기 필요"

T (함정) = K를 놓쳤을 때 나타나는 오류 패턴
           예: 중복 원소를 구별하는 오류
               경우 누락
               조건 분기 미적용
```

### 2.3 루브릭 4축 — TYPE 1

| 축 | 이름 | 무엇을 보는가 | 배점 비중 |
|---|------|-------------|---------|
| 축1 | 개념 | 급소(K) 인식 여부 | 중 |
| 축2 | 조건 | 경우 분류 완결성 | **높음** |
| 축3 | 논리 | 풀이 경로의 구조적 완결 | 중 |
| 축4 | 연산 | 계산 정확성 | 낮음 |

```
TYPE 1의 특징:
축2(조건)가 가장 무겁다.
경우를 제대로 나누지 않으면
연산이 아무리 정확해도 의미가 없다.

연산(축4) 오류가 조건(축2) 오류의 결과라면
축4는 별도 감점 없이 축2 오류로 흡수한다.
```

### 2.4 창의적 풀이 판별 — TYPE 1

```
가장 다경로가 풍부한 유형이다.
근의공식 vs 인수분해,
직접 열거 vs 조합 공식,
좌표계 vs 벡터

루브릭 통과 여부만 확인하면 된다.
경로가 다르면 무조건 alt경로 확인 플래그.
```

## 3. TYPE 2 — 제시문 기반 논술 (국어·사회·역사·도덕)

### 3.1 이 유형의 핵심

```
질문이 묻는 것:
"이 학생이 제시문을 이해하고
 논제에 맞는 논리 구조를 세웠는가"

급소(K)의 성격:
→ 제시문 독해 — 글이 말하는 핵심이 무엇인가
→ 논제 파악 — 무엇에 대해 무엇을 써야 하는가
→ 논증 구조 — 주장-근거-반박의 구조가 있는가

모범답안의 성격:
→ 다경로 허용이 제한적
→ 논지는 다를 수 있지만 논증 구조는 같아야 함
→ 정반대 논지도 구조가 완결되면 인정 (단, 문제 설계에 따라)
```

### 3.2 f(Q) 작동 방식 — TYPE 2

```
M (재료) = 제시문 + 보조 자료
           → 제시문에서 사용 가능한 근거의 범위 파악
           → 출처 명시 요구 여부 확인 ("인명, 저서명 포함")
           → 개념어·키워드 목록 추출

C (조건) = "단 ~ 포함할 것", "A와 B를 비교하여"
           "~의 관점에서", "인명 및 저서명과 함께"
           → 포함 조건의 체크리스트가 축2의 기준
           → 조건 하나 누락 = 축2 감점

R (요구) = "논하시오" → 주장 + 근거 + 반박
           "설명하시오" → 개념 + 사례 + 의미
           "비교하시오" → 공통점 + 차이점 + 시사점
           "쓰시오" → 명칭 + 내용
           → 요구 동사가 논증 구조의 틀을 결정

K (급소) = 제시문의 핵심 논리 또는 논제의 중심 개념
           예: "위정척사 사상이라는 것을 알아야 함"
               "황준헌의 조선책략이라는 것을 알아야 함"
               "원교·근린의 대상 나라가 미국·일본임을 알아야 함"

T (함정) = 제시문 오독, 개념 혼동, 조건 누락
           예: 개화사상으로 혼동
               인명 누락
               근거 없는 주장
               반론 없이 일방 주장
```

### 3.3 루브릭 4축 — TYPE 2

| 축 | 이름 | 무엇을 보는가 | 배점 비중 |
|---|------|-------------|---------|
| 축1 | 개념 | 제시문 핵심 독해 + 급소 파악 | **높음** |
| 축2 | 조건 | 포함 조건 체크리스트 충족 | **높음** |
| 축3 | 논리 | 논증 구조 완결성 (주장-근거-반박) | 중 |
| 축4 | 연산 | 해당 없음 (0점으로 설정) | — |

```
TYPE 2의 특징:
축4(연산)이 없다.
그 배점을 축1과 축2에 재배분한다.

축1과 축2가 같은 무게를 갖는다.
"무엇을 알아야 하는가" + "조건을 다 채웠는가"
이 둘이 TYPE 2 채점의 핵심이다.

축3(논리)은 글의 구조를 본다.
"논하시오"이면 주장-근거-반박이 있는가.
"설명하시오"이면 개념-사례-의미 순서가 있는가.
요구 동사가 축3의 판정 기준을 결정한다.
```

### 3.4 요구 동사별 논증 구조 맵

```typescript
const ARGUMENT_STRUCTURE_MAP = {
  "논하시오":   ["주장", "근거(제시문)", "반론", "재반박"],
  "설명하시오": ["개념", "내용", "사례 또는 근거"],
  "비교하시오": ["A의 특징", "B의 특징", "공통점", "차이점"],
  "서술하시오": ["핵심 내용", "구체적 설명"],
  "쓰시오":    ["명칭 또는 개념", "내용"],
  "비판하시오": ["대상의 주장", "비판 근거", "대안"],
};
// 요구 동사가 축3의 판정 기준이 된다
```

### 3.5 창의적 풀이 판별 — TYPE 2

```
정반대 논지의 답안:
→ 루브릭 통과 여부로 판단
→ 논지가 반대여도 논증 구조가 완결되면 인정
→ 단, 문제가 특정 입장을 요구하면 (예: "찬성 입장에서")
   논지 자체가 조건(C)이므로 축2에서 감점

예상 밖의 근거를 사용한 답안:
→ 제시문 내 근거 사용 여부 확인 (M의 범위)
→ 제시문 외 근거는 "출처 명시" 조건 여부에 따라
→ 교사 확인 플래그 + "예상 외 근거 사용" 표시
```

## 4. TYPE 3 — 자료 해석 추론 (그래프·표·실험)

### 4.1 이 유형의 핵심

```
질문이 묻는 것:
"이 학생이 자료에서 패턴을 읽고
 과학적·논리적 추론으로 결론을 도출했는가"

급소(K)의 성격:
→ 자료 독해 — 수치·경향·패턴이 무엇을 말하는가
→ 변수 파악 — 무엇이 원인이고 무엇이 결과인가
→ 추론 근거 — 자료에서 직접 읽히는 것 vs 해석한 것

모범답안의 성격:
→ 추론의 방향은 하나지만 표현 방식은 다양
→ 자료 수치를 근거로 제시했는가가 핵심
→ 결론만 있고 근거 없으면 0점에 가까움
```

### 4.2 f(Q) 작동 방식 — TYPE 3

```
M (재료) = 그래프, 표, 실험 결과, 수치 데이터
           → 제시된 변수와 값의 범위 파악
           → 경향(증가·감소·일정), 특이점, 비교 기준 추출

C (조건) = "단위를 명시하여", "수치를 근거로"
           "경향과 원인을 함께", "글로 설명하시오"
           → 수치 인용 여부가 중요한 조건이 됨
           → 그래프를 그려야 하는 경우 그래프 형태도 조건

R (요구) = "경향을 설명하시오" → 패턴 기술
           "원인을 추론하시오" → 인과 관계
           "예측하시오" → 경향 연장
           "비교하시오" → 두 자료 간 관계
           → 요구 동사가 추론의 깊이를 결정

K (급소) = 자료에서 읽어야 하는 핵심 패턴 하나
           예: "S자형 그래프 → 기울기 변화가 힘의 변화"
               "속도 증가 → 가속도 = 기울기 → F=ma"
               "특정 구간에서 급격한 변화"

T (함정) = 자료 오독, 변수 혼동, 근거 없는 결론
           예: 속도를 힘으로 직접 연결
               상관관계를 인과관계로 오인
               수치 없이 "증가했다"만 서술
```

### 4.3 루브릭 4축 — TYPE 3

| 축 | 이름 | 무엇을 보는가 | 배점 비중 |
|---|------|-------------|---------|
| 축1 | 개념 | 자료 독해 + 관련 개념(F=ma 등) 적용 | 중 |
| 축2 | 조건 | 수치 인용, 단위 명시, 그래프 형태 | 중 |
| 축3 | 논리 | 자료→패턴→원인→결론의 추론 사슬 | **높음** |
| 축4 | 연산 | 계산이 있는 경우 정확성 | 낮음 |

```
TYPE 3의 특징:
축3(논리)이 가장 무겁다.
자료 해석 문제의 핵심은 추론의 사슬이다.

자료 → 패턴 인식 → 원인 추론 → 결론 도출

이 사슬 중 하나가 끊기면 축3 감점.
결론이 맞아도 사슬이 없으면 낮은 점수.

수치를 근거로 제시했는가(축2)가
사슬의 시작이므로 중요도가 높다.
```

### 4.4 손글씨 + 이미지 혼합 처리 — TYPE 3 특이사항

```
그래프를 직접 그려야 하는 경우:
→ IMAGE_RECOGNITION_SPEC.md의 [FIGURE: 설명] 처리
→ 그래프 형태를 텍스트로 기술 (예: "종 모양", "선형 증가")
→ 축 레이블, 방향, 특이점 포함 여부 확인
→ 교사가 그래프 완성도를 직접 판단

표에서 특정 값을 읽어야 하는 경우:
→ 이미지 인식으로 수치 추출
→ 신뢰도 0.85 미만이면 교사 확인 플래그
```

### 4.5 P(무대) 인식 규칙 — 실험 절차 서술

```
근거: HMOS_CORE_SPEC §3.1 P(상황·Context) / §3.2 두 층위

실험 절차 서술은 P(무대)다.
P는 심층 인식요소 — 무대를 먼저 읽어 세운다 (선행 인식).
P가 세워진 뒤에야 그 위에서 B·C가 작동한다.

컴파일 방향: P(심층) → B·C(표층)로 하강
```

#### P 신호 두 가지

```
(1) "~한다" 동작·절차 서술의 나열
    예: 준비한다 / 실에 매달아 관찰한다 / 바꾸어 반복한다
        자화되지 않은 상태로 만든다 / 극을 반대로 하여 수행한다

    [확정 1] 최소 개수:
      "~한다" 절이 둘 이상 이어질 때 P로 본다.
      하나만으로는 무대인지 단순 서술인지 애매 → P 아님.
      단, 무대 명시구(신호 2)가 함께 있으면 "~한다" 하나여도 P.

    [확정 2] 예외 — 아래는 "~한다"로 끝나도 P가 아니다:
      "~의 값을 구한다"  → Q (목적지)
      "~라 한다"         → D (정의)
      예외는 이 둘로 시작한다. 지금 더 늘리지 않는다.
      오탐이 실제로 나오면 그때 추가한다.

(2) 무대 명시구
    "그림과 같이", "다음과 같이", "아래와 같이", "실험 과정"
```

#### 작동

```
P가 잡히면:
  → 그 절차들을 C로 흡수하지 않는다. 무대로 세운다.
  → B·C·Q는 그 P 위에서 인식한다.
  → P 선행 → B·C 하강. 컴파일 방향을 유지한다.

금지:
  절차 서술을 P/C 애매 후보로 두고
  7형식 맥락(B·C가 먼저 잡혔다는 이유)으로 C 확정하는 것.
  B·C가 P보다 먼저 서면 컴파일 방향이 거꾸로 된다.
```

#### [확정 3] 절차 안의 "~할 때" — P와 C 이층 유지

```
예: "A를 실에 매달아 자석의 N극을 가까이 했을 때 A의 움직임을 관찰한다"

절 전체를 P로 뭉개지 않는다.
  무대(P)는 P대로 세운다       — 실에 매달아 … 관찰한다
  그 안의 "~했을 때"는
  그 위에 C로 따로 세운다       — N극을 가까이 했을 때

P와 C는 층이 다르다 (CORE_SPEC §3.1·§3.2):
  P = 무대 (심층, 선행 인식)
  C = 무대 위 특정 순간 포착 (표층, 조건 격리)

금지 (양방향):
  절차(P)를 C로 삼키는 것   ✗
  C를 P로 삼키는 것         ✗
  → 이층을 유지한다.
```

#### 오식별 사례 — 이 규칙이 메우는 공백

```
문항: 2026학년도 6월 모평 물리학Ⅰ 5번 (자성 실험)

현재 f(Q) (규칙 반영 전):
  "~할 때"(C.조건)와 "~를"(B.목적격)이 먼저 잡혀 B+C+Q 맥락이 섰고,
  절차 서술 6개 절이 P/C 후보에서 전부 C로 확정됐다.
  → 5형식(B+C+Q), P 없음
  → K = C₈ "때" (오식별)

원인: 절차 서술을 P로 세우는 신호가 없어서
      무대가 C로 뭉개졌다.

[별도 문제] K가 "때"라는 조각이 된 것은
  "[결과 표: N극 가까이 했을 때 …]"가 "때"에서 절로 끊긴 탓도 겹친다.
  이는 절 분할 문제로, 이 P 규칙과 따로 다룬다.
```
