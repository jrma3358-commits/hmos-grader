## 7. 2차 화면 분석 — 문항 검증 결과 수정 (PHASE A)

이 화면이 첫 번째보다 더 중요하다.
1차 구현에 PHASE A (루브릭 설계)도 있었음을 확인한다.

### 7.1 화면 위치
```
채점 업무 / 시험지/문항 관리 / 문항 검증 결과 수정
```

### 7.2 문항 3단 구성 (작동 확인)
```
좌: 문항 원문
중: 모범답안
우: OCR
```

### 7.3 채점 기준 섹션 분류 (작동 확인)
```
수학적 모델링:
  1번 20% - 현상과 변수 정의가 명확함
  2번 25% - 일차함수 또는 이차함수 식을 타당하게 구성함
  3번 25% - 식을 세운 이유를 수학적으로 설명함

해석과 평가:
  4번 15% - 모델의 의미를 실제 상황과 연결해 해석함
  5번 15% - 모델의 한계점과 개선 방안을 제시함
```

오늘 설계한 루브릭 4축과 동일한 구조.
섹션 분류까지 구현됐음이 확인된다.

### 7.4 인정-보정 기준 카테고리 (작동 확인)
```
인정 기준:
  현상 선택 다양성 인정   100%  논리가 타당하면 어떤 현상이든 인정
  일차·이차 선택 인정     100%  둘 중 하나를 선택하고 이유가 타당하면
  가정값 인정             90%   실제 수치가 아닌 가정값도 명확하면

부분 인정:
  부분 모델링 인정         50%  변수 정의, 함수식, 설명이 모두 있음
  한계점 부족 보정         70%  한계점과 개선 방안 모두 구체적임

오답 조건:
  수학식 누락              %    함수식이 명확히 없음
```

### 7.5 정답 가이드 구조 (작동 확인)
```
허용 답안 (alt경로 목록):
  - 선택한 현상이 다양해도 논리가 타당하면 인정
  - 일차·이차 중 어느 것이든 이유가 타당하면 인정
  - 가정값이어도 일관되면 인정
  - 변수 이름이 x, y, t, W 등 달라도 의미가 명확하면
  - 그래프, 표, 말 설명 함께 사용해도 함수식 확인되면

오답 조건 (축 미충족):
  - 현상만 있고 함수식 없음
  - 변수 의미 불명확
  - 함수식과 현상 연결 설명 거의 없음
  - 일차·이차가 아닌 식 + 이유 없음
  - 한계점과 개선 방법 모두 누락
```

이것이 오늘 설계한 오답 조건 + alt경로 허용 답안 구조다.

### 7.6 상태 자동 판정 (작동 확인)
```
상태: 채점 가능
필수 기준/판정 규칙: 6/3
```

오늘 설계한 QUESTION_DESIGN_SPEC의
objectivity_score: CLEAR 판정과 동일하다.

### 7.7 상단 버튼 목록 (확인)
```
MCP 프롬프트 / 채점기준입력 / OCR 원본 /
HMOS / 답안 / 채점기준 / 목록
```

### 7.8 이 화면이 알려주는 것

```
1차 구현 흐름:
  출제자: 문항 + 모범답안 입력
      ↓
  PHASE A: 루브릭 설계 (이 화면)

  PHASE B: 학생 답안 채점 (첫 번째 화면)
```

## 8. 3차 화면 분석 — 네비게이션 + 인정보정 카테고리

### 8.2 답안 일괄 등록 (신규 확인)

```
학생 답안을 한 번에 여러 개 업로드하는 기능
```

## 9. 4차 화면 분석 — 채점 완결 화면 (가장 완전한 구현 증거)

### 9.1 5단계 워크플로우 (완전 확인)

```
인식 대기 → 인식 확인 → 채점 대기 → 채점 확인 → 확정
(풀이입력)  (AI 풀이)   (인식완료)   (AI 채점)   (최종확정)

각 단계에 HMOS MCP ID가 찍혀 있음
모든 단계가 MCP 호출로 연결됨
```

### 9.2 alt_ 코드 체계 (핵심 발견)

```
루브릭 항목마다 alt_ 코드가 있음

alt_condition    문항 조건 보수    20%  ✓
alt_principle    실근 조건 원리    20%  P (부분)
alt_relation     연속 관계 설정    20%  P (부분)
alt_development  식 전개·후보추출  20%  ✓ (수정인정)
alt_conclusion   최종 결론         20%  ✓

재개발 시 이 alt_ 코드 체계를 유지할 것
ENGINE_SPEC의 K→축1, C→축2, R→축3 구조가
실제로는 5개 항목으로 분화됨
```

### 9.3 채점 점수 구조

```
Matrix 점수 (유사도): 76.666% = 3.83점
Plus (루브릭 가산):   +0%
최종 점수:            4.0

→ 유사도(Matrix) + 루브릭(Plus) 병렬 구조

재개발 선택지:
  옵션 A: Matrix + Plus 병렬 유지 (1차와 동일)
  옵션 B: 루브릭 단일 기준 (오늘 스펙 원칙)
```

## 11. 6차 화면 분석 — 국어 논술 TYPE 2 두 번째 학생 (비교 증거)

### 11.1 두 화면이 함께 중요한 이유

```
같은 문항 (10번) + 같은 루브릭 + 다른 학생 + 다른 점수

고갱이: 4.5점  Matrix 54.1675%
늪휘:   1.5점  Matrix 16.6675%

→ "채점 기준은 하나다" 실물 증거
   같은 루브릭이 두 학생에게 일관되게 적용됨
```

### 11.2 루브릭 판정 비교

```
항목             고갱이 (4.5점)    늪휘 (1.5점)
────────────    ──────────────   ──────────────
자료2개 연결     ✓                ✓
예상 반론        ✓                ✓
반박             ✓                ✗  ← 차이
반박의 자료근거  ✗                ✗
────────────────────────────────────────────
새론 판정        P (부분)          X (0점)
조직 판정        P                 P
출처 판정        ✓                 X (0점)

→ 반박 하나 차이로 P와 X가 갈림
→ 루브릭이 정확하게 변별함
```

### 11.3 Matrix 스펙트럼 완성

```
TYPE 1 수학:      Matrix 76.666%  → 4점
TYPE 2 국어 상위: Matrix 54.168%  → 4.5점
TYPE 2 국어 하위: Matrix 16.668%  → 1.5점

→ Matrix 16%에서도 루브릭으로 정확한 채점 가능
→ 유사도가 채점 기준이 아님을 수치로 증명
→ 채움AI가 이 학생에게 낮은 점수를 줄 수 없는 이유
   (어휘가 적어 유사도 낮으면 낮은 점수)
→ HMOS는 루브릭이 기준이므로 정확한 1.5점
```

### 11.4 피드백 비교 — 같은 루브릭, 다른 맞춤 피드백

```
고갱이: "잘한 것 인정 + 반박만 추가하면 됨"
늪휘:   "최소 인정 + 출처와 반박 둘 다 필요"

→ 같은 루브릭 → 학생별 맞춤 피드백
→ CLAUDE.md "잘한 점 먼저" 원칙 두 학생에 각각 적용
```

### 11.5 두 화면이 확인하는 것

```
1. 같은 루브릭이 일관되게 적용됨 (채점 기준 단일성)
2. 변별력이 정확함 (4.5점 vs 1.5점)
3. 피드백이 학생별로 다름 (맞춤 피드백)
4. Matrix 낮아도 루브릭으로 정확한 채점 (유사도 한계 극복)
5. 이 두 화면이 교사 시연의 핵심 장면이 될 수 있음
```

### 11.6 교사 시연 활용

```
POC 시연 시나리오:
  1. 같은 문항에 두 학생 답안을 입력
  2. 같은 루브릭으로 채점
  3. 4.5점과 1.5점이 나오는 것을 보여줌
  4. 각 학생에게 다른 피드백이 나오는 것을 보여줌

→ "채점 기준은 하나인데 왜 점수가 다른가?"
→ 루브릭이 학생의 실력을 정확히 반영함
→ 교사가 납득할 수 있는 채점 = 합의의 기반
```
