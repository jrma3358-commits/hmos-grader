# HMOS 문항분석 솔루션 — 조립설명서 (C·논술 9단계)
### 오종래 확정 원칙 기반 · 2026-10-13

---

## HMOS 절대 원칙 (오종래 2026-10-13)

- 논제를 5색+급소로 인식한다 (엔진).
- 제시문에서 논제 급소와 닿는 급소를 추출한다 (엔진).
- 논제 급소 ↔ 제시문 급소를 대조해 연관성 강약을 판정한다 (엔진).
- AI는 엔진이 잡은 연결 결과를 문장으로 구성할 뿐이다.
- 엔진이 못 잡은 것은 AI로 채우지 않는다. 엔진을 먼저 고친다.

---

## 0. 이 문서의 자리

이것은 C·논술 문항분석 솔루션이 어떤 순서로 작동해야 하는지의 조립설명서다.
코드와 Claude 프롬프트는 이 순서를 따른다. 코드에 맞춰 이 문서를 고치지 않는다.

- 이 문서는 `HMOS_문항분석_조립설명서.md`(2026-10-07, 5단계)를 9단계로 넓힌 것이다.
- 4·5·6·9단계의 세부 규칙은 `HMOS_논제생성_명세서-2.md`(2026-09-28)를 따른다. 각 단계에 출처 절을 적는다.
- 8단계 루브릭의 조각·요소·충족조건·배점은 `HMOS_루브릭_구현명세-7.md` F2~F6을 따른다.

## 1. 전체 원칙

- **논제를 먼저 읽는다. 급소가 확정되면 제시문에서 그 실체를 찾는다.**
  제시문은 토양·바다 — 논제가 방향을 잡은 뒤 정보를 추출하는 곳이다.
  제시문을 먼저 읽으면 방향 없이 헤엄치게 된다.
- **엔진이 주도한다. Claude는 엔진 근거 기반으로만 답한다. 교사는 확정만 한다.**
  - 엔진 산출(5색·노드·급소)은 Claude가 다시 계산하거나 바꾸지 않는다.
  - Claude의 출력은 언제나 근거(단락·근거 문장·엔진 노드)를 함께 낸다.
  - 교사가 확정하기 전까지 AI는 제안만 한다.

## 1단계 — 문항 입력

**담당:** 교사

**입력:** 논제 텍스트 + 제시문 텍스트 (따로 받는다)

---

## 2단계 — 논제 인식

**담당:** HMOS 엔진

**입력:** 논제 텍스트

**처리:** 논제의 5색·급소·C-F(서술형태)를 엔진으로 추출한다.

**논술 논제의 급소 (오종래 2026-10-13):**
- Q(서술하시오·논하시오·설명하시오) = 형식. 급소 아님
- 급소 = Q 앞에 서 있는 B+C 덩어리
  - B = 무엇을 (실체)
  - C = 어떻게·어디서·어떤 조건으로 (방향·범위 제약)
- B 위에 C가 붙은 덩어리가 논제의 실제 급소다

**출력:** 5색 조합 · 노드 · 급소 · C-F

---

## 3단계 — 제시문 분석

**담당:** 엔진 (HMOS 절대 원칙 — 제시문에서 논제 급소와 닿는 급소를 엔진이 추출한다)

**입력:** 2단계 소문항별 논제 급소 + 제시문 텍스트

**처리:** 논제 급소를 기준으로 제시문을 단락별로 읽어 P·B·D·C·급소를 추출한다.
- 단락마다 5색 노드를 엔진 표지로 잡는다 (recognizePassage)
- 단락 급소 = 서두·말미의 B 가운데 논제 급소 keyword를 품은 B. 논제 급소가 먼저, 논제의 다른 B가 다음 (connectPassage)
- 논제 급소와 닿는 B가 없는 단락은 배경 단락이다
- 소문항이 참조한 제시문(공통 발문의 「제시문 [가], [나], [다]를 참고하여」) 안의 단락만 본다
- 참조 범위는 제시문을 목적어로 세운 말(「제시문 [가], [나]를 참고하여」·「(나)를 바탕으로」)만이다. 「제시문 [다]에서 …」·「제시문 [나]와 같이」·「제시문 [가]의 …」는 내용을 가리킬 뿐 범위를 좁히지 않는다 (오종래 2026-10-14)

| 색 | 제시문에서의 역할 |
|---|---|
| P (무대) | 이 글의 배경·상황·시대적 맥락 |
| B (연기자) | 이 글의 주인공·핵심 개념·대상 |
| D (신상) | 연기자의 정의·설명·관계·과거 기록 |
| C (조건) | 연기자가 처한 제약·한계·경계 |
| Q (실체) | 제시문에서 Q는 표면에 드러나지 않는다. B 안에 접혀 있다 |

**원칙:**
- 단락의 급소는 언제나 하나다
- 급소는 언제나 B다. 무대(P)와 신상(D)은 급소가 아니다
- 논제 급소와 연결되는 실체를 찾는 것이 목적이다

(출처: 조립설명서 2026-10-07 「제시문 해석 논리」 · 엔진 제시문 급소 규칙 — 판별 확정 원칙 2026-10-07)

---

## 4단계 — 논제↔제시문 연결 평가 (4축)

**담당:** 엔진 (HMOS 절대 원칙 — 논제 급소 ↔ 제시문 급소를 엔진이 대조해 연관성 강약을 판정한다)

**입력:** 2단계 소문항별 논제 급소 + 3단계 단락 급소

| 축 | 담당 | 판별 |
|---|---|---|
| ① 타당 | 엔진 | 논제 급소 ↔ 제시문 단락 급소 연결선이 있다 |
| ② 비약 (강약) | 엔진 | 연결의 연관성 강약 — **[봉인] 판정 규칙 비어 있음** |
| ③ 불완전 | 엔진 | 제시문 급소 중 논제에 안 온 것 — **엔진 규칙 미구현** (지금 단락 급소는 논제 열쇠로만 선다) |
| ④ 사족 | 엔진 | 논제가 요구하는 실체의 근거가 제시문에 없는 것 — 논제 급소가 제시문 어느 단락 급소와도 연결되지 않으면 사족 (단락 단위, 오종래 2026-10-13) |

**흐름:** 엔진이 ①~④를 낸다. 규칙이 비어 있는 축은 비어 있다고 표시한다 — AI로 채우지 않는다.

**원칙:**
- AI는 엔진이 잡은 연결 결과를 문장으로 구성할 뿐이다. 엔진이 못 잡은 것은 엔진을 먼저 고친다
- 학생 답안을 보는 것이 아니다. 논제와 제시문의 관계를 보는 것이다

(출처: 논제생성 명세서-2 §3-5·§3-5-1)

## 5단계 — 논제 정교화 (4갈래 + 보완)

있는 논제의 의도(급소를 제대로 평가하려는 의도)를 고도화한다. 새 문제 추가가 아니다.

| 갈래 | 진단 | 처방 |
|---|---|---|
| ① 일방흐름 | 급소 k가 너무 쉬움·단조 | 제약 C 추가 |
| ② 서술복잡 | 급소는 있으나 문장이 얽혀 체감 못 함 | 소문항 계단 ((1)(2)(3)) |
| ③ 급소불명확 | 악문 | 재작성 |
| ④ 사족 | 제시문에 논제와 무관한 실체 | 표시·교사 확인 (생성 없음) |
| ⑤ 보완 | 6단계 ⑤에서 넘어온 것 — 소문항이 한 단락에 연결되고, 관계가 선 다른 단락이 그 소문항의 참조 범위 안에 있다 (오종래 2026-10-14) | 핵심은 그대로 두고 그 단락과 실체를 조건으로 끌어들임 |

**원칙:**
- ①②③⑤는 정교화한 논제를 다시 입구(엔진)로 태워 급소가 의도대로 잡히는지 확인한다 (자가검증 순환). ⑤는 제시문과 함께 태워 끌어들인 단락에 연결되는지도 본다
- ④는 표시에서 끝난다 — 문제 생성/재작성으로 이어지지 않는다
- ② 서술복잡의 계단 「(1)(2)(3)」은 2단계가 계단마다 따로 인식한다 (오종래 2026-10-14) — 계단 번호는 「1」, 소문항 안이면 「2-1-1」. 문장 가운데의 「(1)의 변화」는 계단이 아니다. 한 소문항으로 읽으면 B가 다시 셋 이상이 되어 서술복잡이 남는다

**판단 일관성 (오종래 2026-10-14) — Claude가 매번 같은 근거로 판단하게:**
- 서버는 진단마다 작업 블록 하나를 만든다: id · 소문항 · 원 논제 · 엔진 핵심(급소덩어리 B) · 갈래 · 엔진 근거 · 처방 · 반드시 남길 말. 블록은 엔진 값으로만 채운다
- 처방은 갈래마다 고정 문장이다 (① 조건 하나 이상 추가 · ② (1)(2)(3) 계단 · ③ Q 앞 「무엇을+어떻게」 덩어리 · ⑤ 그 단락 기호와 실체를 조건으로). ①②⑤는 엔진 핵심을 글자 그대로 남긴다
- Claude는 블록 id마다 정교화안과 「바꾼 점」만 쓴다. 근거는 Claude가 쓰지 않는다 — 화면의 근거는 엔진 진단 문장이다
- 서버가 점검한다: 남길 말이 빠졌거나 ⑤의 단락 기호가 없거나 재인식에서 그 단락에 연결되지 않으면 「교사 확인」으로 표시한다 (판정하지 않는다)

(출처: 논제생성 명세서-2 §3)

## 6단계 — 추가 논제 생성 (F_인문사회 6유형)

빈 곳을 채우는 논제를 제안한다. AI 자유생성이 아니다. 제시문 단락 급소들의 **관계**에서 논제를 낸다.

**담당:** 엔진 (①②③⑤ — [봉인⑭]) · Claude (④ 논제 문장만)

**입력:** 2·3·4단계 엔진 결과만 쓴다 — 이 밖의 것으로 관계를 정하거나 논제를 만들지 않는다.
- 2단계: 소문항별 인식 (급소·노드)
- 3단계: 단락 급소 (실체·닿은 논제 열쇠·논제 노드) · 단락별 5색 노드
- 4단계: 소문항 ↔ 단락 연결선 · 참조 범위(scope)

**흐름 (오종래 2026-10-14):**
```
① 단락 급소 비교·대조   엔진 — 3단계 단락 급소를 단락 둘씩 맞대 본다
   ↓
② 관계 유형 판정        엔진 — 유사 / 대비 / 보완 / 병렬
   ↓
③ 관계별 실체 추출      엔진 — 대비: 두 급소의 실체 차이
                               유사: 두 급소의 공통 근거
                               보완: 한 급소가 다른 급소의 빈 곳을 채우는 실체
                               병렬: 같은 층위의 독립 급소 나열
   ↓
④ 6유형 논제 생성       엔진이 관계 → 유형을 정하고, Claude는 ③의 실체로 논제 문장만 쓴다
   ↓
⑤ 기존 논제와 비교      엔진 — 추가 / 보완 / 덮음 판단
                               추가 → 6단계 추가 논제 · 보완 → 5단계 정교화로 넘김 · 덮음 → 내지 않음
```

- 유형 목록은 급소 판별기가 아니라 커버리지 지도다. 급소를 분류하지 않는다.
- 기존 논제를 고치는 「보완」은 5단계 정교화로 간다 (오종래 2026-10-14). 6단계는 ⑤에서 판단만 하고 넘긴다.
- 엔진이 관계를 세우지 못한 단락 쌍은 논제를 내지 않는다 — Claude가 관계를 추정해 채우지 않는다. 엔진을 먼저 고친다.

**유형 지도 (6종):** 비교·대비 / 공통원리 / 근거·주장 / 대안제시 / 선택·응용 / 인연·비판

### [봉인⑭] 단락 관계 규칙 (오종래 2026-10-14 확정)

**① 비교 단위 — 급소 단락.** 소문항마다 4단계가 세운 단락 급소를 모은다 (참조 범위 안, background 제외). 같은 단락에 같은 실체의 급소가 둘이면 하나로 센다. 단락이 다른 급소 둘을 한 쌍으로 맞대 본다 (같은 단락 안의 급소끼리는 «단락 간»이 아니다).

**② 관계 판정 — 위에서부터 먼저 맞는 것.** 「품는다」는 엔진 연결 규칙(`contains` — 한쪽 실체가 다른 쪽을 품고, 품기는 쪽은 두 글자 이상)이다.

| 순서 | 관계 | 조건 (엔진 결과만) |
|---|---|---|
| 1 | 유사 | 두 단락 급소의 실체가 서로 품는다 (같은 실체) |
| 2 | 대비 | 실체는 다르나 닿은 논제 B의 종류가 같다 — 같은 논제 B이거나, 두 논제 B 실체의 첫 어절(주체 자리)을 뺀 어절이 하나라도 같다 (「B국이 시행한 대응조치」·「D국이 시행한 정책」 → 「시행한」, 오종래 2026-10-14) |
| 3 | 보완 | 한 단락 급소의 실체가 다른 단락의 노드(급소 노드 밖) 실체에 품겨 있다 — 그 단락이 이 급소를 다시 다룬다 |
| 4 | 병렬 | 위 셋 아님 — 종류가 다른 논제 B에 닿은, 서로 겹치지 않는 급소 |

**③ 관계별 실체 (엔진 산출).**

| 관계 | 실체 |
|---|---|
| 대비 | 기준 = 같은 논제 B, 또는 같은 어절 · 차이 = 두 급소 실체 |
| 유사 | 공통 근거 = 두 단락의 B 노드 가운데 서로 품는 실체 (급소 포함) |
| 보완 | 빈 곳 = 채워지는 급소 · 채움 = 다른 단락에서 그 급소를 품은 노드 (색·실체) |
| 병렬 | 나열 = 두 급소 실체 (각자의 논제 열쇠) |

**④ 관계 → 6유형 (엔진).**

| 관계 | 유형 |
|---|---|
| 대비 | 비교·대비 · 선택·응용 · 인연·비판 |
| 유사 | 공통원리 |
| 보완 | 근거·주장 · 대안제시 |
| 병렬 | 선택·응용 |

- 병렬은 두 핵심이 겹치지 않아 비교가 서지 않는다 — 비교·대비·공통원리는 유사·대비에서만 낸다 (오종래 2026-10-14).
- **비교 불가:** 단락 쌍 가운데 유사·대비가 하나도 없으면 엔진이 「비교 불가」를 표시한다. 그 문항에서는 비교·대비·공통원리 논제가 나오지 않는다.

**④-1 논제 뼈대 (엔진).** 머리는 언제나 「제시문 [A], [B]를 참고하여」 — 엔진이 참조 범위로 읽는다. a·b = 두 단락 급소의 표기, c = 공통 근거 첫 실체, v = 빈 곳의 표기, f = 채움 첫 실체.

- **표기 (오종래 2026-10-14 (A)):** 단락 급소가 4단계에서 소문항의 논제 핵심 덩어리 B에 닿았고 그 B가 급소를 품으면, 뼈대에는 그 B 실체를 쓴다 (「B국」 → 「B국이 시행한 대응조치」, 「정책」 → 「D국이 시행한 정책」). 아니면 급소 그대로. 관계 판정(②)은 급소로 한다 — 표기는 뼈대 문장에만 쓴다.

| 유형 | 뼈대 |
|---|---|
| 비교·대비 | [A]의 a와 [B]의 b를 비교하여 설명하시오. |
| 선택·응용 | [A]의 a와 [B]의 b 가운데 하나를 선택하여 근거를 들어 논하시오. |
| 인연·비판 | [A]의 a의 입장에서 [B]의 b를 비판적으로 서술하시오. |
| 공통원리 | [A]와 [B]에 공통으로 나타나는 c에서 공통 원리를 추출하여 설명하시오. |
| 근거·주장 | [F]의 f를 근거로 [V]의 v에 대한 주장을 뒷받침하시오. |
| 대안제시 | [V]의 v가 지닌 문제를 분석하고, [F]의 f를 바탕으로 대안을 제시하시오. |

- 뼈대는 엔진에 다시 넣어 두 단락에 연결되고 급소가 B로 서는 꼴로 정했다 (사회논술_문_1 실측). 「그 차이를」(지시어가 급소가 됨)·「선택하고,」(동사가 급소가 됨)는 쓰지 않는다.
- 같은 단락 쌍·같은 유형은 하나만 낸다 — 관계 순서(유사→대비→보완→병렬)에서 먼저 선 관계로.

**④-2 논제 문장 (Claude).** Claude는 후보마다 뼈대를 자연스러운 문장으로 다듬고 「기존과 다른 점」·「새로 측정하는 것」을 쓴다. 뼈대의 머리·두 단락 기호·실체는 글자 그대로 남기고, 새 실체·조건·단락을 더하지 않는다. 서버가 실체·기호가 남았는지 점검하고, 쓴 논제를 제시문과 함께 입구(엔진)로 다시 태워 두 단락에 연결되고 급소가 서는지 확인한다 (자가검증). 어긋나면 「교사 확인」으로 표시한다.

**⑤ 기존 논제와 비교 (4단계 연결선·참조 범위).**

| 판단 | 조건 | 행선 |
|---|---|---|
| 덮음 | 어느 소문항이 두 단락 모두에 연결선이 있다 | 내지 않음 |
| 보완 | 어느 소문항이 한 단락에 연결선이 있고, 다른 단락이 그 소문항의 참조 범위 안이다 | 5단계 정교화 진단 「⑤ 보완」 (그 소문항, 끌어들일 단락) |
| 추가 | 위 둘 아님 | 6단계 추가 논제 (④ 뼈대) |

- 같은 소문항·같은 끌어들일 단락의 보완은 하나만 넘긴다.

**출력:**
