# HMOS 문항분석 솔루션 — 조립설명서 (C·논술 9단계)
### 오종래 확정 원칙 기반 · 2026-10-13

---

## HMOS 절대 원칙 (오종래 2026-10-13)

- 논제를 5색+급소로 인식한다 (엔진).
- 제시문에서 논제 급소와 닿는 급소를 추출한다 (엔진).
- 논제 급소 ↔ 제시문 급소를 대조해 연관성 강약을 판정한다 (엔진).
- AI는 엔진이 잡은 연결 결과를 문장으로 구성할 뿐이다.
- 엔진이 못 잡은 것은 AI로 채우지 않는다. 엔진을 먼저 고친다.

---

## 0. 이 문서의 자리

이것은 C·논술 문항분석 솔루션이 어떤 순서로 작동해야 하는지의 조립설명서다.
코드와 Claude 프롬프트는 이 순서를 따른다. 코드에 맞춰 이 문서를 고치지 않는다.

- 이 문서는 `HMOS_문항분석_조립설명서.md`(2026-10-07, 5단계)를 9단계로 넓힌 것이다.
- 4·5·6·9단계의 세부 규칙은 `HMOS_논제생성_명세서-2.md`(2026-09-28)를 따른다. 각 단계에 출처 절을 적는다.
- 8단계 루브릭의 조각·요소·충족조건·배점은 `HMOS_루브릭_구현명세-7.md` F2~F6을 따른다.

## 1. 전체 원칙

- **논제를 먼저 읽는다. 급소가 확정되면 제시문에서 그 실체를 찾는다.**
  제시문은 토양·바다 — 논제가 방향을 잡은 뒤 정보를 추출하는 곳이다.
  제시문을 먼저 읽으면 방향 없이 헤엄치게 된다.
- **엔진이 주도한다. Claude는 엔진 근거 기반으로만 답한다. 교사는 확정만 한다.**
  - 엔진 산출(5색·노드·급소)은 Claude가 다시 계산하거나 바꾸지 않는다.
  - Claude의 출력은 언제나 근거(단락·근거 문장·엔진 노드)를 함께 낸다.
  - 교사가 확정하기 전까지 AI는 제안만 한다.

   ↓

## 1단계 — 문항 입력

**담당:** 교사

**입력:** 논제 텍스트 + 제시문 텍스트 (따로 받는다)

---

## 2단계 — 논제 인식

**담당:** HMOS 엔진

**입력:** 논제 텍스트

**처리:** 논제의 5색·급소·C-F(서술형태)를 엔진으로 추출한다.

**논술 논제의 급소 (오종래 2026-10-13):**
- Q(서술하시오·논하시오·설명하시오) = 형식. 급소 아님
- 급소 = Q 앞에 서 있는 B+C 덩어리
  - B = 무엇을 (실체)
  - C = 어떻게·어디서·어떤 조건으로 (방향·범위 제약)
- B 위에 C가 붙은 덩어리가 논제의 실제 급소다

**출력:** 5색 조합 · 노드 · 급소 · C-F

---

## 3단계 — 제시문 분석

**담당:** 엔진 (HMOS 절대 원칙 — 제시문에서 논제 급소와 닿는 급소를 엔진이 추출한다)

**입력:** 2단계 소문항별 논제 급소 + 제시문 텍스트

**처리:** 논제 급소를 기준으로 제시문을 단락별로 읽어 P·B·D·C·급소를 추출한다.
- 단락마다 5색 노드를 엔진 표지로 잡는다 (recognizePassage)
- 단락 급소 = 서두·말미의 B 가운데 논제 급소 keyword를 품은 B. 논제 급소가 먼저, 논제의 다른 B가 다음 (connectPassage)
- 논제 급소와 닿는 B가 없는 단락은 배경 단락이다
- 소문항이 참조한 제시문(공통 발문의 「제시문 [가], [나], [다]를 참고하여」) 안의 단락만 본다

| 색 | 제시문에서의 역할 |
|---|---|
| P (무대) | 이 글의 배경·상황·시대적 맥락 |
| B (연기자) | 이 글의 주인공·핵심 개념·대상 |
| D (신상) | 연기자의 정의·설명·관계·과거 기록 |
| C (조건) | 연기자가 처한 제약·한계·경계 |
| Q (실체) | 제시문에서 Q는 표면에 드러나지 않는다. B 안에 접혀 있다 |

**원칙:**
- 단락의 급소는 언제나 하나다
- 급소는 언제나 B다. 무대(P)와 신상(D)은 급소가 아니다
- 논제 급소와 연결되는 실체를 찾는 것이 목적이다

(출처: 조립설명서 2026-10-07 「제시문 해석 논리」 · 엔진 제시문 급소 규칙 — 판별 확정 원칙 2026-10-07)

---

## 4단계 — 논제↔제시문 연결 평가 (4축)

**담당:** 엔진 (HMOS 절대 원칙 — 논제 급소 ↔ 제시문 급소를 엔진이 대조해 연관성 강약을 판정한다)

**입력:** 2단계 소문항별 논제 급소 + 3단계 단락 급소

| 축 | 담당 | 판별 |
|---|---|---|
| ① 타당 | 엔진 | 논제 급소 ↔ 제시문 단락 급소 연결선이 있다 |
| ② 비약 (강약) | 엔진 | 연결의 연관성 강약 — **[봉인] 판정 규칙 비어 있음** |
| ③ 불완전 | 엔진 | 제시문 급소 중 논제에 안 온 것 — **엔진 규칙 미구현** (지금 단락 급소는 논제 열쇠로만 선다) |
| ④ 사족 | 엔진 | 논제가 요구하는 실체의 근거가 제시문에 없는 것 — 논제 급소가 제시문 어느 단락 급소와도 연결되지 않으면 사족 (단락 단위, 오종래 2026-10-13) |

**흐름:** 엔진이 ①~④를 낸다. 규칙이 비어 있는 축은 비어 있다고 표시한다 — AI로 채우지 않는다.

**원칙:**
- AI는 엔진이 잡은 연결 결과를 문장으로 구성할 뿐이다. 엔진이 못 잡은 것은 엔진을 먼저 고친다
- 학생 답안을 보는 것이 아니다. 논제와 제시문의 관계를 보는 것이다

(출처: 논제생성 명세서-2 §3-5·§3-5-1)

## 5단계 — 논제 정교화 (4갈래)

있는 논제의 의도(급소를 제대로 평가하려는 의도)를 고도화한다. 새 문제 추가가 아니다.

| 갈래 | 진단 | 처방 |
|---|---|---|
| ① 일방흐름 | 급소 k가 너무 쉬움·단조 | 제약 C 추가 |
| ② 서술복잡 | 급소는 있으나 문장이 얽혀 체감 못 함 | 소문항 계단 ((1)(2)(3)) |
| ③ 급소불명확 | 악문 | 재작성 |
| ④ 사족 | 제시문에 논제와 무관한 실체 | 표시·교사 확인 (생성 없음) |

**원칙:**
- ①②③은 정교화한 논제를 다시 입구(엔진)로 태워 급소가 의도대로 잡히는지 확인한다 (자가검증 순환)
- ④는 표시에서 끝난다 — 문제 생성/재작성으로 이어지지 않는다

(출처: 논제생성 명세서-2 §3)

---

## 6단계 — 추가 논제 생성 (F_인문사회 6유형)

빈 곳(미측정 유형)을 채우는 논제를 제안한다. AI 자유생성이 아니다.

**유형 지도 (6종):** 비교·대비 / 공통원리 / 근거·주장 / 대안제시 / 선택·응용 / 인연·비판

- 유형 목록은 급소 판별기가 아니라 커버리지 지도다. 현재 논제가 덮는 유형을 대조해 빈 유형을 찾는다.

**출력:**
```
[문항분석]
- 급소(k): ○○
- 현재 측정 역량: ○○
- 빈 곳(미측정 유형): ○○

[추가논제]
- 논제 텍스트

[근거]
- 기존과 다른 점: ○○
- 새로 측정하는 것: ○○
```

(출처: 논제생성 명세서-2 §1·§4·§5)

## 7단계 — 교사 확정

**담당:** 교사

**화면에 보여줄 것:** 2단계 논제 급소 · 3단계 단락별 급소 · 4단계 4축 · 5단계 정교화안 · 6단계 추가 논제 + 근거

**교사가 할 것:** 논제를 선택·수정·확정한다. 확정된 논제가 8단계의 입력이 된다.

---

## 8단계 — 루브릭 생성

**담당:** Claude + 엔진

**입력:** 7단계에서 교사가 확정한 논제

**처리:**
- 확정 논제의 급소(B)에서 채점 축을 도출한다
- 급소가 복수이면 축도 복수다
- C-F(서술형태)가 있으면 서술 방향 축을 추가한다

(출처: 조립설명서 2026-10-07 ⑤ · 루브릭 구현명세 F2~F6)

---

## 9단계 — 모범답안 생성

**담당:** Claude + 엔진

**처리:**
- 조각을 파트 순서(근거대기 → 세우기 → 풀기 → 답구하기 → 표현)로 규칙 전개한다
- 생성 후 편 답을 입구(엔진)로 다시 태워 급소가 논제 인식과 일치하는지 역검증한다 (GJ). 아니면 다시

**성격:** 모범답안은 증인이지 심판이 아니다. 채점 기준은 «급소 도달»이다.

(출처: 논제생성 명세서-2 §2)

## [확정] 오종래 2026-10-13

1. **3단계 담당** — 엔진(`connectPassage`). HMOS 절대 원칙으로 Claude 담당을 거둔다.
2. **3단계 단락 급소의 기준** — 엔진 제시문 급소 규칙 그대로 (논제 급소가 방향). 단락 자체 무게중심 급소 규칙은 엔진에 없다 — ③불완전은 미구현.
3. **2단계 API** — `/analyze` (v2 러너).
4. **1차 필터 [봉인⑧]** — C 흐름에서 뺀다.
5. **5단계 갈래 진단** — 엔진이 [봉인⑬]으로 진단한다 (아래 기준). Claude는 진단된 ①②③의 정교화안만 쓴다. ④는 표시만.
   - ① 일방흐름: 급소 B 바로 다음이 Q이고, 그 단위에 C 노드가 없을 때
   - ② 서술복잡: 단위의 B 노드가 3개 이상이고 C-F 노드가 없을 때
   - ③ 급소불명확: MULTIPLE_CONVERGENCE이거나, Q 앞에 B+C 덩어리가 서지 않을 때 (2026-10-13 수정 — 수렴도 0 기준은 거둔다. 논술 급소는 Q 앞 B+C)
   - ④ 사족: 4단계 ④ 결과(제시문 노드 중 논제와 연결선 없는 것)
   - ①②③은 소문항(엔진 단위)마다 본다
6. **9단계 GJ 판정불가** — 교사 판정으로 넘긴다.
7. **C-F 봉인** — 비어 있으면 「봉인으로 비어 있음」을 표시한다. (2026-10-13 확인: `formPivot = ["C-F"]` 채워져 있음)
8. **7단계 재인식** — 확정 논제를 엔진에 다시 태워 8단계 급소를 엔진 값으로 쓴다.
