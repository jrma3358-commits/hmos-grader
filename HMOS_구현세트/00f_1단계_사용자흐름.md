# HMOS 1단계 문제 인식 솔루션 — 사용자 흐름 (완성)
_2026-09-29. 실체 분석 → 선생 확인 → 정교화/추가논제(삼세번) → 최종 결정 → 루브릭·모범답안 직행._
_선생이 주도한다. 문항이 곧 재료이므로, 수정되면 질문 인식부터 다시._

---

## 0. 핵심 — 선생이 주인인 흐름
코드가 실체를 짚어주고, 선생이 확인·조정하며, 확정하면 루브릭이 나온다.
AI가 통보하는 것이 아니라, 선생이 자기 문제를 확인하고 다듬는다. (판단의 주인 = 선생)

---

## 0½. 두 단계 구조 — 필터 → 루브릭창
문항 인식 단계는 **1차 거르는 필터**다. 이 필터를 통과한(정제된) 문항만 루브릭창으로 넘어간다.

```
[필터 단계 = 1차 거르기]  ← 화면 A
  질문 인식 · 실체 분석 · 선생 확인 · 정교화/추가논제(삼세번)
  역할: 나쁜 문항을 거르고, 좋은 문항으로 다듬는다
    - 급소 불명확(악문)? → 정교화(재작성)
    - 너무 쉬움/복잡? → 정교화(조이기/계단)
    - 평가할 것 빠짐? → 추가 논제
    - 선생 의도 맞나? → 확인
  통과 조건: 최종 결정 (삼세번 이내)
        ↓ 통과 = 화면 전환
[루브릭창 = 다음 단계]  ← 화면 B
  루브릭 · 채점기준 · 부분점수 · 모범답안
  역할: 확정된(걸러진) 문항으로 채점 틀을 생성 (되돌이 없음)
```

- **필터(화면 A)** = 판단·조정 구간. 선생이 주도, 문항을 다듬음, 되돌이(삼세번) 있음.
- **루브릭창(화면 B)** = 생성 구간. 확정된 문항으로 채점 틀을 짓기, 직행.
- 필터를 통과한 문항만 넘어가므로, 루브릭·모범답안이 «좋은 문항 위에» 선다(품질 보장·낭비 없음).
- 개발 대응: 필터 = 앞단(코어 완성 후 붙임) / 루브릭창 = 코어(지금 F4 개발 중).

## 1. 전체 흐름
```
[선생이 문제 입력]
      ↓
┌─→ 질문 인식 (급소 K)
│      ↓
│   실체 분석 (계열별 구조 요약)
│      ↓
│   선생에게 확인 ── 「당신 문제는 이 급소를, 이 구조로 평가합니다」
│      ↓
│   ┌─ 좋음 → [최종 결정 버튼]
│   └─ 수정하겠다 (정교화 / 추가 논제)
│         ↓
│      문항 수정됨 → (삼세번 이내?) ─┐
└──────────────← 처음부터 다시 ──────┘   ※ 수정=새 문항=인식부터 다시
                    ↓ (삼세번 소진 or 선생이 결정)
             [최종 결정] ── 확정, 더 수정 없음
                    ↓
             루브릭 → 채점기준 → 부분점수 → 모범답안  (직행, 되돌이 없음)
```

---

## 2. 실체 분석 (루브릭과 연동, 계열별)
문항 인식(급소·조각) 위에 「실체 분석」을 얹어 선생에게 보여준다.
**루브릭과 같은 조각 분해에서 함께 나온다** — 따로가 아니라 한 몸(급소 = 중심 조각).

### 계열별 실체 분석
- **서술형** — (B·D·P 바탕)와 (K·Q 도달)의 요소·논리·개념의 관계로 요약.
- **논술형** — 제시문 분석(관련 정보·배경) + 논리 분석(논리가 요구하는 핵심 · 논리와 제시문의 관계).

### 실체 분석의 세 역할 (하나가 셋을 한다)
1. **선생 확인의 창** — 「당신 문제는 이것을 이렇게 평가합니다」
2. **정교화·추가논제의 근거** — 이 실체를 보고 고칠지 판단
3. **최종 루브릭의 뿌리** — 확정된 실체로 루브릭이 선다

---

## 3. 선생의 조정 — 두 갈래
- **문제 정교화 (의도 고도화, 모든 서술형 공통)** — 급소 접근성 진단:
  ① 일방(너무 쉬움) → 제약 추가로 조이기
  ② 복잡해 인식 어려움 → 단계별 접근 경로 열기(소문항 계단)
  ③ 불명확(악문) → 정의·식 변경 재작성
- **추가 논제 (계열별)** — 커버리지 빈 곳(못 재는 역량)을 채우는 논제.
- 둘 다 문항을 바꾸는 일 → **바뀌면 질문 인식부터 다시.**

---

## 4. 「삼세번」 원칙 — 되돌이 제한
문항 수정 시 질문 인식부터 다시. 되돌이는 **삼세번**까지 받아준다.
- **1·2·3회차** — 수정 가능 (실체 분석 → 확인 → 정교화/추가논제).
- **삼세번 소진 후** — 최종 결정으로만 (더 수정 불가).

### 의미 — 규율이자 정서
- **계속 고침 = 준비 부족·결정 장애.** 「무엇을 평가할지」가 서 있으면 삼세번 안에 확정된다.
- 삼세번은 받아주되(너그러움), 그 안에 명확히 결정하도록 돕는다(단호함).
- 우리 정서의 「삼세번」 — 몰아세우지 않고 매듭짓는다. 선생을 명확하게 돕는 자리.
- (재지 않고 돕는다가 선생에게 적용되는 형태.)

---

## 5. 최종 결정 버튼 — 되돌이와 직행을 가른다
- **버튼 전 (되돌이 구간)** — 인식·실체·확인·정교화. 문항 바뀌면 처음부터. 무거운 작업 없음.
- **버튼 (확정)** — 선생이 「이 문제다」 결정. (삼세번째엔 강제 확정)
- **버튼 후 (직행 구간)** — 루브릭·채점기준·부분점수·모범답안, 한 번에.
- 낭비 없음: 무거운 산출(루브릭·모범답안)은 확정 후 딱 한 번, 최종 문제로.

---

## 6. 모범답안의 세 갈래 (1차와 3차를 잇는 뿌리)
모범답안은 채점 증인일 뿐 아니라, 문항을 손보고 미래로 잇는 뿌리다.
- **실체 비평 → 문제 정교화** (의도 고도화)
- **상태 비평 → 추가 논제** (빈 곳 채우기)
- **미래 연속 → 논리 특징 → 예비 분야** (3차 네비게이션의 문항 쪽 뿌리:
  이 문항의 논리 특징이 어느 분야로 연속되는가)

---

## 7. 자연스러운 구현 (선생 체감)
「문제 넣으니 → 실체를 짚어주고 → 고칠 것 고치고(고치면 다시 분석) →
됐다 싶으면 최종 결정 버튼 → 루브릭·모범답안 완성.」
클릭 몇 번, 선생이 주도, 삼세번 안에 매듭. 부담 없음.

_선생이 주인, 삼세번으로 매듭, 무거운 산출은 확정 후 한 번._
