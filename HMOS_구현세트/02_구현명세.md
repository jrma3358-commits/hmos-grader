# HMOS 루브릭 생성 — 구현 명세 (클로드 코드용)

> 이론 문서(「루브릭 생성 설계도」)를 코드로 옮기기 위한 **구현 명세**.
> 이론 문서는 「왜」를, 이 명세는 「입력→규칙→출력」을 딱딱하게 적는다.
> `[봉인]` 표시 칸은 오종래가 채운다. 클로드 코드는 채워진 규칙을 **호출만** 하고,
> 규칙 내용을 스스로 지어내지 않는다. `[봉인]`이 비어 있으면 그 함수는 구현 보류.

---

## 0. 경계 — 이 모듈이 하는 것 / 안 하는 것
- **안 함**: 급소·조합을 잡는 일. → 그건 질문 인식(HMOS, 이미 구현)이 함. 이 모듈은 급소를 **입력으로 받는다**.
- **함**: 받은 급소·조합에서 조각을 뽑아 루브릭·채점기준·모범답안·문항평가를 **한 번에** 낸다.

---

## 1. 입력 (질문 인식 HMOS의 산출)
```
입력 = {
  문항텍스트: string,        // 구조정보 포함 (밑줄=[밑줄:…], 수식 등)
  계열: "수리" | "인문사회국어",
  조합: 요소[]  ,            // 예: ["b","d","c","q"]  (HMOS가 준 것)
  급소_k: {
     실체: string,          // "질문이 요구하는 실체" (HMOS 산출)
     // 필요한 다른 필드는 HMOS 산출 형식에 맞춰 추가
  }
}
```
> 주의: 조합·급소는 이 모듈이 다시 계산하지 않는다. HMOS 출력을 그대로 받는다.

---

## 2. 자료구조 — 조각 객체 (넷을 동시에 담는 그릇)
한 조각이 루브릭·채점기준·부분점수·모범답안을 **동시에** 담으려면 아래 필드를 가진다.
```
조각 = {
  id: string,
  파트: "근거대기" | "세우기" | "풀기" | "답구하기",   // 세로축
  요소: "q"|"p"|"d"|"b"|"c"|"k" | null,                 // 가로축. ①②④는 요소, ③⑤는 null(수행)
  수행질: "정확성" | null,                              // ③풀기=연산정확성 (⑤표현/논리성은 소거)
  확인물음: string,        // 기본 물음을 이 문항 실체로 매치한 것 (규칙①)
  충족조건: string,        // 이 조각을 «맞췄다»고 볼 조건 (규칙⑥의 판정 근거)
  is_중심: boolean,        // k 중심 조각인가
  배점: number,            // 규칙④·조각수에서 산출
  모범조각: string         // 이 조각이 답에서 어떻게 펴지는지 (모범답안 구성단위)
}

루브릭 = 조각[]            // 조각 목록 그 자체
채점기준 = 각 조각의 {충족조건, is_이분:true}
부분채점기준 = 파트별 { 조각수, 배점합, 맞춘수→점수 }
모범답안 = 조각[].모범조각 을 출구-조립으로 엮은 것 (별도 모듈)
문항평가 = 분해 과정에서 발생한 경고 목록 (아래 5)
```
> 핵심: 조각 하나에 파트·요소·충족조건·배점·모범조각이 다 있으면, 조각 목록을 만드는 순간 넷이 동시에 나온다.

---

## 3. 함수 명세 (각 함수 = 입력·출력·규칙)

### F1. 파트투영(문항텍스트, 조합) → 파트별 확인물음
- 출력: { 근거대기:물음, 세우기:물음, 풀기:물음, 답구하기:물음 }
- 규칙: `[봉인①]` 네 파트를 문항 실체로 매치하는 판정 기준.
  - 기본 물음(고정): d=정의 이해 / b=개념·성질 / p=상황 / c=조건 의미 / q=질문 요구 / k=실체 도달
  - 매치: 기본 물음의 «실체»를 이 문항에서 뽑아 끼움. → **무엇으로 뽑나 = [봉인①]**
  - (구현 선택: 규칙기반 / LLM호출 중 무엇? — 정해야 함. LLM이면 봉인 없이 흉내 위험)

### F2. 조각역산(파트별물음, 급소_k, 5색인식결과) → 조각[]   ★핵심
- 출력: 조각 객체 배열 (충족조건·배점 제외한 뼈대까지)
- 규칙: `[봉인②]` 각 파트에서 조각 수를 «급소에서 역산한 최소 핵심 수»로 센다.
  파트마다 «무엇을 세는가»가 다르다:
  - **① 개념 / ② 세우기** = 그 단계에 **호출되는 5색 실체 객체 수**
    (①: b·d 개념·정의 객체 / ②: c·p 조건·상황의 구체화 객체)
    → 5색 인식 결과가 «호출한 객체»를 주므로 그 개수를 센다. (인식 재사용 — 수월)
  - **③ 풀기** = **세워진 식(②)에 따라 «완성된 식의 결과» 개수**. 각 결과의 정확성을 O/X.
    - 풀기 = 세워진 식의 연산 과정의 정확성 판단.
    - 조각 = 계산에 참여한, 세워진 식에 따른 «완성된 식의 결과» 하나하나.
    - 조각 수 = 완성된 식 결과의 개수. 부분점수 = 정확한(O) 결과 수.
    - «세워진 식에 따른» → ②세우기에 종속. ②가 틀리면 그에 따른 ③결과도 X (게이트 내장).
    → 요소가 아니라 «수행». «분기점»보다 «완성된 결과»가 O/X 단위로 명확하다.
  - **④ 답구하기** = **「급소에 관계된 정확한 대상」과 「급소가 요구한 값」의 일치 여부**로 센다 (k·q 한 몸).
    - 대상(k, 무엇을 구하는가)과 요구값(q, 어떤 값으로)을 «따로» 세지 않고, 둘의 «일치»로 조각을 판단.
    - 정확한 대상에 요구된 값이 맞게 닿았나 = O / 대상이 엉뚱하거나 값이 틀리면 = X.
    - 구할 실체가 여럿이면 «대상-값 일치» 짝도 여럿 → 그만큼 조각.
    - 예) |α+β|: 대상=α+β, 요구값=절댓값 √5 → «α+β를 잡고 그 절댓값이 √5인가»가 조각 하나.
    - ③과의 구분: ③은 «계산이 맞나», ④는 «그 결과가 급소가 요구한 대상·값에 닿았나».
      계산은 맞는데 질문이 요구한 게 아니면 ③=O, ④=X.
  - 문항 조건 수를 그냥 세는 게 아니라, k에 닿는 데 필요한 핵심만.
  - **①②는 인식이 호출객체를 주어 세기 쉬움. ③(완성 결과)·④(대상-값 일치)는 과정·답 구조를 한 겹 더 읽어야 함.**

### F3. 요소색판정(조각) → "q"|"p"|"d"|"b"|"c"|"k"|null
- 규칙: `[봉인③]` 조각이 어느 요소인지 가르는 기준. **파트가 후보를 좁힌다:**
  - ① 근거대기 → b·d 중
  - ② 세우기 → c(수리)·p(논술) 중
  - ④ 답구하기 → k·q 중
  - ③ 풀기 → 요소 아님(null), 수행질="정확성"
  - (⑤ 표현/논리성 파트는 채점에서 소거 — 네 파트로 운영)
  - 즉 백지에서 색을 가르는 게 아니라, 파트에 따라 후보가 정해진다 (봉인② F2와 함께 정해짐).

### F4. 충족조건명세(조각) → string
- 규칙: `[봉인⑥]` 이 조각을 «맞췄다»고 볼 이분(O/X) 경계.
  - 채점 때 학생 답을 이 조건에 대조. 생성 때 미리 명세.
- **O/X 경계는 「질문의 요구와 정답 사이의 일치」로 판단하되, 계열에 따라 갈린다:**
  - **닫힌 정답(수리 등) → 완전 일치만 O.** 급소가 «값»이라 값이 정확히 맞아야 도달.
    (실제 채점표: «풀이가 맞는 경우에만 정답»)
  - **열린 인문(논술 등) → 급소에 닿으면 O.** 급소가 «논지»라 표현·경로가 달라도
    질문이 요구한 실체(논지·주장)에 닿았으면 인정.
    (실제 채점표: «합당한 과정이면 정답», «다른 표현도 인정»)
  - 둘 다 «급소 도달로 O/X»라는 골격은 같다. 급소가 값(닫힘)이냐 논지(열림)냐에 따라
    엄격·관대가 갈릴 뿐 — «기본 골격 + 계열 조정»이 O/X 경계에서도 작동한다.
  - 이 «질문 요구 ↔ 정답 일치» 판정은 출구 검산(봉인⑤)과 **같은 동작이므로 하나로 확정한다** (아래 GJ).

### GJ. 급소일치판정(답, 질문요구, 계열) → O/X   [봉인⑤⑥ 통합]
- **봉인⑤(출구 검산)와 봉인⑥(이분 경계)은 하나의 판정기다.** 둘 다 «답 ↔ 질문의 요구»를
  급소로 대보는 같은 동작이고, 대는 대상만 다르다.
- 입력: 어떤 답(모범답안이든 학생답이든) + 질문의 요구(급소) + 계열
- 처리: 답을 **입구 로직(급소 인식, 이미 구현됨)으로 태워** 급소를 뽑고, 질문의 급소와 대본다. (입구 재사용)
- 경계: 닫힌 정답=완전 일치 / 열린 인문=급소 도달 (계열별)
- 출력: O/X
- **쓰이는 곳 둘 (같은 판정기, 다른 입력):**
  - 모범답안 생성 검산 (⑤): AI가 지은 답을 대봄 → 급소 일치하면 완결, 아니면 다시.
  - 학생답 채점 (⑥): 학생이 낸 답을 대봄 → O/X.
- 개발 압축: 판정 로직을 둘 만들지 않고 하나가 생성·채점 양쪽에 쓰인다.
  그 하나가 «입구 로직의 재사용»이라, 새로 만들 게 아니라 있는 걸 재사용한다.
  («입구와 출구는 한 부품» — 검산이든 채점이든 입구로 답을 재는 하나의 판정기.)

### GJ-다경로. 모범답안에 없는 풀이(다경로) 채점
학생이 모범답안과 «다른 경로»로 풀면, 모범답안과 대조해 «틀림」으로 깎지 않는다.
경로는 자유이되 급소에 닿으면 맞다 — 그 다경로를 공정하게 채점하는 흐름:

```
학생이 모범답안과 다른 경로로 풀었다
  ↓
① 루브릭(조각)과 대조        — 모범답안이 아니라 급소(조각)로 본다
  ↓
② 근거 역산 (출구-분해)      — 이 답안이 어느 급소·조각에 닿았나 거슬러 읽는다
  ↓
③ 학생 로직대로 모범답안 추가 생성 — 이 경로로 끝까지 가면 이렇게 된다(경로별 견본)
  ↓
④ 부분점수 측정              — 그 생성본에 대보아 조각 O/X → 부분점수
  ↓
⑤ 선생님 확인 「선택」         — 애매하면 사람이 최종 확인 (판단의 주인은 사람)
```

- 판정 기준은 여기서도 «급소 도달»이지 «모범답안 일치»가 아니다.
- 모범답안은 하나가 아니라 **학생 경로마다 추가 생성**된다(F6 재사용, 경로 자유·여러 견본).
- ③의 생성본도 GJ로 검산한다 — 학생 경로가 급소에 닿는 «합당한 경로»인지.
  (실제 채점표: «합당한 과정을 통해 이끌어냈으면 정답».)
- ⑤ 선생님 확인은 **선택**이다 — AI가 다경로를 채점하되, 새 경로가 애매하면
  사람에게 최종 확인권을 넘긴다. AI가 다 안다고 우기지 않는다.
- 자취: 「이 학생은 이 경로로 이 조각까지 닿았다」가 근거로 남는다(다경로도 블랙박스 아님).

### GJ 두 갈래 정리
- **단일 경로** (학생 답이 모범답안과 같은 결): 바로 조각 O/X.
- **다경로** (모범답안에 없는 풀이): 위 5단계 흐름 → O/X + 선생님 확인 선택.
- 어느 쪽이든 심판은 급소(루브릭)이고, 모범답안은 증인·참고다.

### F5. 배점산출(조각[], 총배점) → 조각[].배점
- 규칙: `[봉인④]` **두 층으로 배점한다. 파트 지수는 고정이다(AI가 흔들 수 없음).**
  - **1층 — 파트 지수(고정 2:3:2:2:1):**
    ```
    ① 근거대기 2 : ② 세우기 3 : ③ 풀기 2 : ④ 답구하기 2   (합 9)
    ※ ⑤ 표현/논리성 파트는 채점에서 소거함(AI 재현성 편차가 큰 자리).
      배점은 네 파트 지수 합(9)으로 정규화하거나, 필요 시 총배점에 맞춰 재정규화.
    파트 배점 = 총배점 × 파트지수 / 9
    ```
    이 비율은 **모든 문항 고정**이다. 문항마다 AI가 조정하지 않는다 —
    조정하면 채점 공정성이 AI 재량에 흔들린다. 문항별로 달라지는 것은
    **조각 수뿐**이며, 비율은 골격(공정성), 조각 수는 살(타당성)이다.
    (계열별로 지수가 갈릴 수는 있음 — 논술은 ⑤ 비중이 커질 수 있으나,
     그 역시 계열마다 «고정»이지 문항마다 조정이 아니다. `[봉인④-계열]`)
  - **2층 — 파트 안에서 조각 수로 균등 분배:**
    ```
    조각당 배점 = 파트 배점 ÷ 그 파트 조각 수
    예) ②세우기 3점, 2조각 → 1.5점씩
    ```
  - **k(급소)의 중심성은 배점이 아니라 게이트로 실현한다.**
    ④(k) 조각을 못 맞추면 배점을 더 깎는 게 아니라(그러면 배점이 흔들림),
    다른 파트에 **상한**을 건다(«순서 상한»). 배점은 고정, k의 무게는 게이트.
  - 반올림 처리: `[봉인④-a]` 나눠떨어지지 않을 때.

### F5-note. 부분점수의 두 시점 — 생성 때 틀, 채점 때 구체화
- **생성 때**: F2가 센 파트별 조각 수가 «배점 틀»을 확정한다 (몇 조각=몇 점). 아직 학생 답은 보지 않는다.
- **채점 때**: 학생 답을 각 조각에 대보며 «맞춘 조각 수»로 부분점수를 구체화한다.
  - 이때 **모범답안은 «참고 견본»으로 옆에 선다** — 「이 조각이 이렇게 채워지면 맞음」의 예시.
  - 그러나 판정 기준은 «급소 도달»이지 «모범답안 일치»가 **아니다**.
    학생 경로가 모범답안과 달라도 조각의 급소에 닿으면 맞음.
    (실제 채점표: «합당한 과정을 통해 이끌어냈으면 정답», «다른 표현도 인정»)
  - 즉 모범답안은 증인이지 심판이 아니다 — 채점 때도 참고로 서되 판정을 대신하지 않는다.

### F6. 모범답안생성(조각[], 급소_k, 질문인식) → 모범답안
- 규칙: `[봉인⑤]` **조각을 «질문 인식 기반 규칙»으로 편다** (출구-조립). LLM 자유 생성이 아니라 규칙 전개.
  - **모범답안 = 조각을 파트 순서로 규칙에 따라 이어 편 것:**
    근거대기 → 세우기 → 풀기 → 답구하기 → 표현.
  - 각 조각의 «펴는 방식»은 질문 인식이 준 정보(급소·요소)를 따른다:
    - ①개념 조각 → 인식이 호출한 b·d를 명시
    - ②세우기 조각 → 인식이 준 c·p를 식/논지로 규칙대로 표현
    - ③풀기 조각 → 세운 식을 연산해 완성 결과로
    - ④답구하기 조각 → 급소 대상에 요구값을 맞춰 도달
    - ⑤표현 조각 → 논리적으로 마무리 서술
  - **왜 규칙인가**: LLM 자유 생성이면 «그럴듯하나 급소를 벗어난» 답이 날 수 있다.
    질문 인식이 정한 규칙을 따라 펴면 애초에 급소를 따라가므로 벗어남이 적다.
    (모범답안에서 시작해 짜맞추는 «쉬운 길»의 정반대 — 원천에서 출발한다.)
  - **검산**: 편 답을 GJ(급소일치판정)로 검산. 통과하면 완결, 아니면 다시 편다.
    (GJ가 이중 안전장치. 규칙 전개 + GJ 검산.)
  - **자유의 범위**: 경로는 자유이되 급소 일치하면 됨 → 여러 견본을 낼 수 있다.
    여러 개면 «이렇게도, 저렇게도 급소에 닿는다»를 보여 심판 함정을 더 확실히 피한다.
  - **되돌림 한도**: `[봉인⑤-a]` GJ 검산 실패가 N회 반복되면 «악문 신호»로 문항평가에 넘긴다.

## 3½. 채점 실행 명세 — 조각 O/X 체크로 부분점수

### G1. 채점(학생답, 루브릭, 모범답안) → 채점결과
- 각 파트마다, **F2가 센 조각 수만큼 평가 기준(조각)이 서 있다.**
- 학생 답을 각 조각에 대보아 **O/X 이분 체크** (봉인⑥, 판정 기준=급소 도달).
  - 모범답안은 «이 조각이 이렇게 채워짐»의 **참고**로 옆에 선다 (심판 아님).
- **파트 부분점수 = O인 조각의 배점 합.**

```
채점결과 = 파트마다 {
  조각별: [ {조각id, O|X, 배점, 판단근거}, ... ],   // 조각 수 = 체크 항목 수
  파트점수: Σ(O인 조각의 배점),
}
전체: {
  부분점수: Σ 파트점수 (게이트 상한 적용),
  무너진지점: 최초 X가 난 파트,
  약점: X난 (파트 × 요소),
}
```

### 파트 구성 (⑤ 소거 반영)
채점 파트는 **①근거대기 ②세우기 ③풀기 ④답구하기** 네 파트. ⑤표현/논리성은 소거.
(급소 도달이 핵심이고, 논리성 판정은 편차가 커 빼는 것이 재현성에 유리.)

### 출력 꼴 (판단 근거 = 자취)
점수만 내지 않고 **O/X 체크리스트를 자취로** 낸다.
```
② 세우기  [조각 2개]
   ├ ②-1 근과 계수로 α+β 표현?  [O]  1.5점
   └ ②-2 근과 계수로 αβ 표현?   [X]  0점
   파트점수 1.5/3
...
부분점수 8/9   |  무너진 지점: ③풀기  |  약점: ③ 연산 분기점 1개 놓침
```
- O/X가 곧 판단 근거이자 자취다. «왜 이 점수인가»가 체크리스트로 그대로 드러난다.
- 게이트(봉인④/규칙): 선행 파트가 X면 후행 파트에 상한(«(1) 맞아야 (2) 인정»).

## 6. 문항 생성 (F_gen) — 급소 k 인식 기반으로 시작·연동

> **고정 원칙**
> 문항 생성은 **HMOS를 이용한 문항의 질문·급소 k 인식에서 시작**한다.
> AI 자유 생성이 아니라, 급소 인식(입구)을 기반으로 출발하는 것으로 **고정**하고,
> F1~F6·GJ와 **한 엔진으로 연동**한다. 그 전(급소 인식 없이)에 만들면 일반 AI 문항 생성과 다르지 않다.
> 상세 흐름은 별도 문서 «HMOS_논제생성_명세서.md»를 따른다. 여기서는 연동 위치만 고정한다.

### F_gen 두 갈래 (둘 다 급소 k 인식에서 시작)
- **F_gen-정교화 (의도 고도화, 모든 서술형 공통)** — 있는 문제의 급소 접근성을 진단해
  ① 제약 추가(조이기) ② 단계별 접근 경로 열기 ③ 정의·식 변경 재작성. 있는 문제의 의도를 높인다.
- **F_gen-추가논제 (계열별)** — 급소·역량 커버리지의 빈 곳을 찾아 그 빈 곳을 채우는 논제 생성
  (F_인문사회 · F_경제). 없던 것을 더한다.

### 입출력 (연동)
```
입력: 기존 문항 → [급소 k 인식 = 입구, 이미 구현] → 급소·조각·역량·커버리지
        ↓
F_gen-정교화 : 급소 접근성 진단 → 세 갈래 처방 → 정교화된 문항
F_gen-추가논제 : 커버리지 빈 곳 → 추가 논제
        ↓
출력: 새/정교화 문항  →  자가검증(GJ로 다시 태워 급소가 의도대로 잡히나) → 확인 순환
```

### 연동 고정점
- 시작점은 **언제나 급소 k 인식**이다 (입구 재사용). 별도 생성 엔진을 만들지 않는다.
- 검증점은 **GJ**다 (생성/정교화한 문항을 입구로 다시 태워 급소 일치 확인).
- 즉 F_gen은 «입구(급소 인식) → 처리 → 출구(GJ 검산)»로 F1~F6·GJ와 같은 엔진 위에 선다.

## 7. 미정·결정 필요 (코드 전에 정할 것)

> 아래는 모두 **«급소 k 인식 기반 시작»을 고정**한 위에서 정하는 세부다.
> 시작점(급소 인식)과 연동(같은 엔진)은 이미 고정 — 미정이 아니다.

- [ ] **F1 매치 방식** — 규칙 기반으로 고정 (LLM 호출은 흉내 위험). 물음=고정 틀, 실체=조각에서 «그대로 대입», AI 재작성 금지. → 사실상 «규칙 기반»으로 방향 정해짐, 세부만 확정.
- [ ] **급소_k 출력 형식** — HMOS v2(recognizeV2Analysis)의 pivot 산출 스펙에 맞춰 확정 (표지사전 연결 후).
- [ ] **조각 충족조건 형식** — 자연어 vs 판정가능 구조. 채점 O/X가 가능하려면 판정가능 구조 권장.
- [ ] **문항평가 경고 처리** — «생성 중단(악문)» vs «경고만». F6·F_gen 자가검증 실패 N회 시 악문 신호로.
- [ ] **F_gen 자가검증 루프** — GJ 검산 실패 반복 시 몇 회까지 재시도하고, 안 되면 악문으로 넘길지.

## 8. 재현성 검증 (AI 편차 측정·관리)

> AI(LLM)는 확률적이라 같은 입력에도 결과가 흔들릴 수 있다(재현성 편차).
> 명세의 골격은 편차를 줄이도록 설계됐으나, 실제 편차는 **돌려봐야** 안다. 이 절은 그 측정·관리를 규정한다.

### 편차 예측 (구간별)
| 구간 | 편차 예측 | 이유 |
|------|----------|------|
| 조각 수 · 배점 · 부분점수 | 거의 0 | 세기(count)·계산 — 결정적 |
| 닫힌 정답(수리) 채점 | 매우 작음 | 완전 일치 판정 |
| 급소 인식 · 색 판정 | 봉인 규칙의 결정성에 달림 | 규칙이 촘촘하면 작음 |
| 열린 인문(논술) 채점 | 관리 대상 | 급소 도달 판단 여지 |

- 핵심: 「세고 계산하는」 채점 골격은 편차가 거의 없다(범용 AI가 점수를 통째로 뱉어 편차 큰 것과 반대).
  편차의 관건은 **급소 인식과 논술 판정**이며, 이는 봉인 규칙이 얼마나 결정적인가에 달렸다.

### 재현성 검증 절차
- **반복 측정**: 같은 문항·같은 학생 답을 **N회(예: 10회)** 넣어 결과 일치율을 측정한다.
  - 급소 k 일치율 / 조각 수 일치율 / O/X 일치율 / 부분점수 편차 폭.
- **구간별 기록**: 위 표의 구간마다 따로 측정 — 어디서 편차가 큰지 국소화.
- **논술 별도**: 열린 인문(논술)은 편차가 클 수 있으므로 별도 표본으로 측정.
- **봉인 규칙 환류**: 편차가 큰 지점은 봉인 규칙(급소·색 판정)의 «여지»가 원인일 수 있다.
  규칙을 더 결정적으로 다듬어 편차를 줄인다(오종래, 봉인).

### 편차를 «0»이 아니라 «관리 가능»으로
- 어떤 AI도 편차 0을 보장하지 못한다. HMOS의 방향은 편차를 없애는 것이 아니라 **드러내고 잡는** 것:
  - **자취** — 편차가 나면 어디서 났는지 근거로 드러난다(블랙박스는 원인도 모름).
  - **선생님 확인 선택**(다경로) — 애매하면 사람이 최종 확인해 편차가 오답으로 굳지 않게.
  - **계열 경계** — 닫힌 정답은 편차 0에 수렴, 열린 인문만 관리.
- 「절대 안 틀린다」가 아니라 「틀릴 수 있으나 드러나고 잡힌다」가 신뢰의 실체다.

## 9. 클로드 코드 개발 규율
- `[봉인]`이 빈 함수는 **인터페이스만** 만들고 본체는 보류(호출부만 구현).
- 봉인 규칙을 코드에 직접 쓰지 말고 별도 봉인 모듈에서 import.
- manual mode, 한 단계씩. 파일 쓰기 3점검. API 키 환경변수.
- **시작은 언제나 급소 k 인식** — F_gen도 급소 인식에서 출발하는 것으로 고정.
- F2(조각역산)부터 검증: 문항 하나 넣어 조각이 나오는지 → 오종래 손산출과 대조.
