# HMOS 서논술형 채점 — 인수인계 문서
_이 문서 하나로 어디까지 왔고 무엇부터 이어갈지 잡는다. 새 대화 시작 시 먼저 읽을 것._
_최종 갱신: 2026-09-27_

## 0. 한 문단 요약
질문 인식(급소 추출)은 HMOS 엔진으로 **구현·실증 완료**. 그 위에 «루브릭 → 채점기준 →
부분점수 → 모범답안»의 **설계·명세·순서도가 다 섰고, 봉인 규칙 ①~⑥도 채워짐**.
지금은 그 코드를 **기존 급소 추출 코드에 이어붙여 연속 코드로 구현하는 단계**.
남은 일: F2(조각 역산)부터 코드 구현 → 실제 문항으로 검증 → 손산출과 대조.

## 1. HMOS 핵심 원리 (흔들리면 안 되는 축)
- **급소가 뿌리**: 질문을 읽어 급소(k)를 잡으면 q·조각·루브릭·모범답안이 다 거기서 나온다.
  급소가 q를 정하고 q에 급소가 있다. 논제 «유형»은 겉모습이지 원인이 아니다(유형 판별기 불필요).
- **모범답안 = 증인, 심판 아님**: 채점 기준은 «급소 도달»이지 «모범답안 일치»가 아니다.
  경로는 자유이되 질문 인식과 일치하면 됨.
- **조각 = 레고, 이분**: 맞췄나/못. 부분점수 = 맞춘 조각 수.
- **한 분해가 넷을 낳음**: 조각 분해 한 번에 루브릭·채점기준·모범답안·문항평가 동시 생성.
  생성은 동시, 사용은 각자 시점.
- **입구와 출구는 한 부품**: 답을 입구 로직(급소 인식)으로 재는 하나의 판정기(GJ).
- **기본 골격 + 계열 조정**: 골격이 공정성, 조정이 타당성. AI가 골격(배점 등)을 흔들면 안 됨.

## 2. 다섯 요소 · 네 파트 · 다섯 기본물음
- 요소: q(질문) p(상황) d(정의) b(개념·성질) c(제약) k(급소)
- 계열 기본: 수리=(b·d·c·q) 정의바탕 / 인문사회국어=(p·c·b·q) 상황바탕
- 네 파트(세로축, 순서이자 분류, 계열 공통, ②③만 이름 갈림):
  ① 근거대기  ② 세우기(수리=식/논술=논지)  ③ 풀기(계산/논증)  ④ 답구하기  (+⑤ 표현)
- 다섯 기본물음 ↔ 파트 ↔ 요소:
  - ① 개념 이해했나 → 근거대기 → b·d
  - ② 조건·상황을 식/논지로 구체화했나 → 세우기 → c(수리)·p(논술)
  - ③ 연산/논증을 정확히 했나 → 풀기 → 수행(정확성), 요소 아님
  - ④ 급소 값·실체에 도달했나 → 답구하기 → k·q
  - ⑤ 옳게 구하고 서술했나 → 표현 → 수행(논리성), 요소 아님
- 배점 지수(고정, AI가 못 흔듦): **① 2 : ② 3 : ③ 2 : ④ 2 : ⑤ 1** (합 10). 계열마다 고정.

## 3. 봉인 규칙 ①~⑥ (다 채워짐 — 알맹이는 오종래가 봉인 모듈에)
- ① 파트투영: 네 파트를 문항 실체로 매치 (기본물음 → 확인물음)
- ② 조각역산(★심장): 파트별로 조각 수를 센다
  - ①② = 호출된 5색 실체 객체 수 (인식이 줌)
  - ③ = 세워진 식에 따라 «완성된 식 결과» 수
  - ④ = 급소 대상 ↔ 요구값의 «일치» 수 (k·q 한 몸, 겹쳐 세지 않음)
- ③ 색판정: 파트가 요소 후보를 좁힘 (①→b·d, ②→c/p, ④→k·q, ③⑤→수행)
- ④ 배점·게이트: 고정 지수 2:3:2:2:1 → 파트배점 ÷ 조각수. k는 배점 아닌 «게이트»로.
- ⑤⑥ 통합 = **GJ 급소일치판정**: 답을 입구로 태워 급소 대조. O/X.
  경계 계열별: 닫힌정답(수리)=완전일치 / 열린인문(논술)=급소도달.
  생성 검산(⑤)·채점 판정(⑥) 양쪽에 쓰이는 하나의 판정기.

## 4. 모범답안 생성 (F6, 봉인⑤)
- 조각을 «질문 인식 기반 규칙»으로 편다 (LLM 자유생성 아님).
- 파트 순서(근거대기→…→표현)로 규칙 전개 → GJ 검산 (이중 안전장치).
- 경로 자유라 여러 견본 가능. N회 검산 실패 → 악문 신호(문항평가).

## 8. 개발 운영 규율 (반드시)
- 기존 급소 추출 코드는 **절대 수정 금지** (실증됨). 뒤에 덧붙이기만.
- manual mode, 한 단계씩 승인. 자문자답으로 다음 단계 스스로 실행하면 Esc.
- 봉인 규칙은 코드에 직접 안 쓰고 봉인 모듈 import. 문서만으로 지어내면 흉내(=실패).
- 파일 쓰기: 대상·백업·값노출 3점검. 봉인 값은 화면·로그에 개수·유무만.
- API 키(OCR 등) 환경변수. 하드코딩 금지.
- 검증은 «되나 안 되나»가 아니라 «어디서 헛도나»를 본다. 예측(클로드 판단)과 실증(엔진 산출) 구분.
