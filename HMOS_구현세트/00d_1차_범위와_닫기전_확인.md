# HMOS 문제 인식 솔루션 1차 — 범위와 닫기 전 확인
_2026-09-28. 「1차 탑재 기능을 닫는다」의 정확한 뜻과, 닫기 전 확인·미결 정리._

---

## 0. 한 줄
1차 «설계»는 닫아도 된다(설계·명세·순서도·봉인 다 섬). 단 «설계 닫음 ≠ 완성».
닫은 뒤 남는 것은 «구현·검증»이며, 그 전제는 **표지사전(논리스위치 json) 연결**이다.

---

## 1. 1차 탑재 기능 (질문 인식 위에 얹히는 다섯)
1. **문항 명세 분석** — 각 서논술형을 급소·조각·역량으로 분석.
2. **루브릭·부분점수** — 고정 물음 틀 + HMOS가 뽑은 실체를 «그대로» 대입.
   (AI가 문구를 지어내지 않음. 물음=고정 틀, 실체=조각에서 그대로.)
3. **모범답안** — 조각을 «질문 인식 기반 규칙»으로 펴기 → GJ 검산.
4. **문제 보강** — 문항분석으로 흠(조각 겹침·급소 흐림·요소 결손) 찾아 다듬기.
   «조각이 깔끔 = 평가에 맞음».
5. **추가 논제 추출** — 급소 지정 → 문항 구성 → 자가검증(입구로 급소 잡히나).

## 2. 「닫는다」의 정확한 뜻 — 세 층으로 구분
- **1차 설계**: 설계·명세·순서도·봉인 ①~⑥ 완결. → **지금 닫아도 됨.** ✓
- **1차 구현**: 표지사전 연결 → F2~GJ 코드 → 문항 검증. → 「닫기」가 아니라 **다음 단계**.
- 즉 «설계를 닫되, 그게 곧 작동 완성은 아니다»를 분명히 한다.
  (안 그러면 «닫았는데 안 돌아»의 혼선.)

---

## 3. 닫기 전 확인 — 5가지

### ① [최우선·전제] 표지사전 연결
- 급소 인식(v2)이 hmos-grader에서 돌아야 1차 기능이 그 위에 얹힌다.
- 현재: 논리스위치 json(14개 완성)을 표지사전.json/v2가 **연결 안 함** → switches 비어보임.
- 이것부터 풀어야 실제로 돈다. (설계 닫기와 별개로 필수)

### ② 검증이 아직 0
- 다섯 기능 다 «설계는 있으나 코드 검증 안 됨». 검증된 건 급소 인식(입구)뿐.
- 1차를 «검증까지»로 볼지 «설계까지»로 볼지 정할 것.
- 권고: **1차=설계 완결+급소 인식 검증. 구현·검증은 1차 구현 단계로 따로.**

### ③ 보강·논제생성의 자가검증 루프 (실패 처리 미정)
- 생성/보강한 문항을 입구로 다시 태워 급소가 의도대로 잡히나 검증(GJ 재사용).
- 「몇 번 시도하고 안 되면 어떻게」(악문 신호?)가 미정. 생성 기능 닫으려면 정할 것.

### ④ 세 입장별 출력 (교사·학부모·학생) — 1차? 2차?
- 하나의 명세 → 세 겹 표현:
  - 교사: 명세 전체(급소·조각·역량).
  - 학부모: 결론+쉬운 말(내부 용어 뺌, 점수의 이유).
  - 학생: 약점과 처방(어디서 왜 틀렸나 → 다음에 뭘).
- **주의**: 역량지수를 학부모·학생에 «숫자」로 주면 낙인 위험. 밖으로는 «서술」로 번역.
- 이 출력 설계를 1차에 넣을지 2차로 미룰지 정할 것.

### ⑤ 봉인/코드 최종 경계
- 다섯 기능에서 «봉인(오종래 원천)은 무엇 / 코드(구현)는 무엇»을 선 긋기.
- 봉인: 급소 판정·조각 역산·색 판정·표지 매칭(논리스위치 json).
- 코드: 흐름·호출·틀 대입·출력. 코드가 봉인을 지어내지 않게.

---

## 4. 권고 순서
1. **표지사전 연결** 풀기 (①, 전제) → 급소 인식 hmos-grader에서 작동 확인.
2. **1차 설계 닫기** — 위 다섯 기능 설계 완결 선언(문서로).
3. ③④ 결정 — 자가검증 실패 처리 / 세 입장 출력 1차·2차 구분.
4. **1차 구현 단계 진입** — F2 → F1·F3·F4·F5 → F6 → GJ, 각 검증.
5. 문항 검증 → 오종래 손산출·실제 채점표 대조.

---
_핵심: 설계는 닫되 «완성»과 구분. 표지사전 연결이 전제. 검증은 구현 단계에서._
_역량지수 등 내부 지표는 밖(학부모·학생)으로 낼 때 «서술」로 번역 — 드러내되 상처 안 주게._
