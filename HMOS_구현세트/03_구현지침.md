# HMOS 서논술형 채점 — 구현 지침 (클로드 코드용)

> 이 문서 + 두 설계 문서(「루브릭 생성 설계도」, 「채점 파트 분해 설계」)를 읽고 구현한다.
> 봉인 규칙(조각을 실제로 뽑는 알고리즘, 색 판정, k 무게)은 이 문서에 없다 — 별도 봉인 자산에서 불러 쓴다.
> 이 문서만으로 조각을 지어내지 말 것. 흐름(파이프라인)만 구현하고, 규칙은 봉인 인터페이스로 호출한다.

## 1. 전체 흐름
```
질문 인식(급소 k) → 네 파트를 문항에 투영 → 각 파트에서 조각 수 산출(급소 역산)
   → { 루브릭 · 채점기준 · 부분채점기준 · 모범답안 }  (한 번에 생성)
   → (학생 답 입력 시) 채점 실행 → 부분점수 + 무너진 지점 + 약점 국소화
```

## 2. 네 파트 (세로축, 계열 공통)
- ① 근거대기 — 질문·제시문 이해
- ② 세우기 — (수리)식 세우기 / (논술)논지 세우기
- ③ 풀기 — (수리)계산 / (논술)논증·서술
- ④ 답구하기 — 급소 k에 닿는 결과·결론

파트는 **순서이자 분류**: 앞이 무너지면 뒤에 상한(순서) + 각 파트 독립 채점(분류).

## 3. 조각 (파트 × 요소 교차점)
- 각 파트를 이 문항에 투영해 내용을 채운다 (예: ①=근과 계수의 관계를 아는가).
- 각 파트의 조각 수 = **급소에서 역산한, 옳게 나타내는 데 필요한 최소 핵심 수**.
  - 문항 조건 수를 세는 게 아니라, k에 닿는 데 반드시 필요한 핵심만 센다.
- 조각은 **이분**: 맞췄나 / 못 맞췄나.

## 4. 네 산출의 꼴 (한 번에 생성)
- **루브릭**: 파트별 조각 목록.
- **채점기준**: 각 조각의 이분 판정. (조각을 세면 이미 서 있음 — 따로 안 만듦)
- **부분채점기준**: 파트별 { 조각 목록, 조각 수, 맞춘 수 → 점수 }. 파트 조각 수가 배점 요소.
- **모범답안**: 조각을 다 채운 견본. 출구-조립(자유 생성 → 입구로 검산). 심판 아닌 증인.

## 5. 채점 실행 (학생 답 입력 시)
- 학생 답을 네 파트로 분해 → 각 파트에서 조각을 맞췄나 판정(이분).
- 산출 세 겹:
  1. 부분점수 = 맞춘 조각 수
  2. 무너진 지점 = 어느 파트부터 어긋났나
  3. 약점 국소화 = 어느 파트 × 어느 요소

## 6. 봉인 인터페이스 (코드가 호출만, 구현 안 함)
- `분해규칙(문항, 급소) → 파트별 조각목록`  ← 봉인
- `역산조각수(파트, 급소) → 최소 핵심 수`     ← 봉인
- `k무게규칙(조각) → 배점 가중`               ← 봉인
- `색판정(요소) → q/p/d/b/c/k`               ← 봉인
코드는 이 인터페이스를 **호출**하는 흐름만 구현한다. 규칙 자체를 지어내면 흉내가 된다.

## 7. 구현 규율
- manual mode 유지. 한 단계씩 승인.
- 파일 쓰기(writeFileSync 등)는 대상·백업·값노출 3가지 확인 후 승인.
- 봉인 값(색·조사·어미·매핑 내용)은 화면·로그에 개수·유무만.
- API 키는 코드에 하드코딩 금지 — 환경변수.
- 자문자답으로 다음 단계 스스로 실행 금지. 한 단계 후 멈춤.
