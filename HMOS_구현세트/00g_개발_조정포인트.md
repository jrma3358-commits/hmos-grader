## 0. 결론 먼저 — 지금 코드는 안 건드려도 된다
오늘 새로 나온 것(실체 분석·선생 확인·삼세번·최종 결정 버튼)은
**루브릭 «앞단」의 사용자 흐름**이다. 지금 하는 F4(충족조건)·루브릭 코어는 그 **뒤에** 온다.
→ 지금 F4 개발은 그대로 진행. 조정은 «순서상 위치」와 «명세 추가」이지 «코드 되돌림」이 아니다.

## 1. 무엇이 어디에 얹히나 (순서상 위치)
```
[앞단 — 오늘 새로 나온 사용자 흐름]
  질문 인식 → 실체 분석 → 선생 확인 → 정교화/추가논제(삼세번) → 최종 결정 버튼
        ↓ (확정된 문제로)
[코어 — 지금 개발 중]
  F1 파트투영 → F2 조각역산 → F3 색판정 → F4 충족조건 → F5 배점 → F6 모범답안 → GJ
```
- **앞단**은 루브릭 «전」이다. 지금 코어 개발과 겹치지 않는다.
- 즉 지금 F4를 만드는 것은 «최종 결정 버튼 이후」의 코어. 앞단은 나중에 붙인다.

## 2. 지금(코어)에 바로 조정할 것 — 작음
### (a) F2 산출에 「실체 분석」 추가 (넷 → 다섯)
- 지금 F2 조각 분해가 낳는 것: 루브릭·채점기준·모범답안·문항평가.
- **+ 실체 분석**(조각의 구조 요약)을 다섯 번째 산출로. 루브릭과 같은 조각에서 나오므로 연동.
- 계열별: 서술형=(B·D·P)-(K·Q) 관계 / 논술형=제시문+논리.
- ※ F2 «코드」를 지금 고칠 필요는 없다. 실체 분석은 «조각을 요약해 출력」하는 얇은 추가라,
  F4·F5·F6 다 선 뒤 «출력 정리」로 붙여도 된다. 명세에만 지금 적어둔다.

### (b) F4(지금 작업) — 그대로 진행
- 충족조건은 앞단과 무관. 계열별 O/X 경계(닫힘=완전일치/열림=급소도달) 그대로.

## 3. 나중(앞단 붙일 때) 개발할 것 — 명세만 준비
루브릭 코어(F1~GJ)가 선 뒤에 붙인다. 지금은 명세로만 준비:
- **실체 분석 출력** — 선생에게 보여줄 «확인 창»(급소·구조 요약, 봉인값은 개수·유무만).
- **선생 확인 UI** — 「맞다 / 정교화 / 추가논제」 선택.
- **정교화·추가논제** — HMOS_논제생성_명세서.md 의 F_gen. (급소 인식 기반)
- **삼세번 게이트** — 되돌이 카운터(고정 3회). 1·2·3회 수정 가능, 소진 후 최종 결정 강제.
- **최종 결정 버튼** — 확정 시 루브릭(F1~)로 직행. 확정 전엔 루브릭 생성 안 함(낭비 방지).
- **수정=재인식** — 문항 바뀌면 질문 인식(입구)부터 다시. (입구 재호출)
