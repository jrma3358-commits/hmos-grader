## 진단 요약 (왜 v2가 안 돌았나)
- v2(recognizeV2Analysis)는 **급소 규칙이 맞다**. 다만 봉인 파일 markers가 비어(null) 실행이 막힘.
- v1은 돌지만 K가 틀림(C로 떨어짐) — 쓰지 않음. **v2를 살려서 F2로 잇는다.**
- 즉 F2 코드 짜기 전에, **표지사전.json의 봉인 3자리부터 채워야** v2가 급소를 낸다.

## 채울 자리 3개 (표지사전.json)

### ① markers  (가장 중요)
- **현재**: 1~13행이 `null`. (0행만 `[]` 빈 배열)
- **문제**: null이면 `sw.markers is not iterable`로 즉시 멈춤 (graph.ts:100),
  undecided()도 `s.markers.join(...)`에서 멈춤 (sealed/index.ts:86).
- **채울 규격**: `string[]` (문자열 배열). 빈 배열 `[]`도 허용.
  - 실제 자리표시는 `~`, 공백은 `\s*`로 넣는다(진단 코드가 그렇게 읽음).
  - 각 행(switch)에 그 표지의 실제 문자열 배열을 넣는다. ← 봉인 내용(오종래)

### ② kind  (같이 고쳐야 함)
- **현재**: 14행 전부가 허용 3종 «밖». 그래서 markers만 채워도 노드 0개 → NO_B에서 멈춤.
- **채울 규격**: 아래 셋 중 하나로, **글자 그대로**:
  - `"조사·어미"`  → 노드 (급소 후보)
  - `"연결어"`    → 간선
  - `"부사"`      → 간선
  - ※ 가운뎃점은 반드시 `·` (U+00B7). 다른 문자 쓰면 안 걸림.
- 각 행의 kind를 그 표지의 성격에 맞게 셋 중 하나로. ← 봉인 내용(오종래)

### ③ apply.convergenceWeights  (수렴 가중치)
- **현재**: 없음. 그래서 모든 B의 수렴도가 0으로 «동점» →
  B가 둘 이상이면 MULTIPLE_CONVERGENCE로 감(급소 못 정함).
- **없을 때 기본값**: 연결어 1 · 부사 1 · adjacent 0.
- **채울 규격**: `apply` 객체 안에 `convergenceWeights` 키. 수렴 가중치 값.
  - 이것이 «급소(k)로 조각이 수렴」하는 무게를 정한다 → 오늘 이론의 k 수렴과 직결.
  - ← 봉인 내용(오종래): 어느 표지·관계에 얼마의 수렴 무게를 줄지.

### (참고) id 타입
- id가 14행 모두 «숫자」인데 스키마는 string 기대 (sealed/schema.ts:18).
- 실행은 되나(중복 없음) 타입 어긋남. 여유 될 때 string으로 맞추면 깔끔.

## 채운 뒤 확인 순서 (다음 세션)
1. 표지사전.json에 ①markers ②kind ③convergenceWeights 채운다 (봉인, 오종래).
2. v2 돌려 급소 확인:
   - 명령 예: `recognizeV2Analysis('문장')` → graph.nodes/edges 개수, pivot(급소) 확인.
   - 연속함수 표본문항이면 급소가 «x=2 좌우극한 일치로 a 결정」에 닿는지 본다.
3. v2가 급소를 «낱개 배열(elements)»로 내는지 확인 (v1은 join으로 뭉쳐 개수 못 셈).
4. 그 위에 **F2(조각 역산)** 이어붙이기 — 낱개 배열을 받아 파트별 조각 수 셈.
5. 실제 문항으로 검증 → 오종래 손산출·실제 채점표 배점과 대조.

## 규율
- 표지사전.json은 봉인 — 오종래가 직접 채운다. 클로드 코드가 markers/kind 내용을 지어내면 흉내(=실패).
- 기존 급소 추출(v1/v2) 코드는 수정 금지. 봉인 파일(데이터)만 채운다.
- manual mode, 한 단계씩. 봉인 값은 화면·로그에 개수·유무·타입만.
- 클로드 코드 자문자답(다음 단계 스스로 입력)이 뜨면 지운다(Esc). 오늘도 한 번 발생.
- Auto-update failed(claude.exe in use)는 다른 세션 닫고 재시작하면 해결. 작업엔 지장 없음.
