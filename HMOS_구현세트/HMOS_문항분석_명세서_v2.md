# HMOS 문항 분석 명세서 — 서술형 · 논술형
_2026-09-29. 계열별 실체 분석 절차와 구현 방법. 문항 인식(1차 필터)의 핵심._

## 0. 위치와 성격
- 문항 분석 = **1차 필터**. 문항 인식 위에서 «이 문항이 제대로 섰나」를 거른다.
- 통과한(정제된) 문항만 루브릭창으로. 실체 분석은 **루브릭과 같은 조각 분해에서** 나온다(연동).
- 계열(서술형/논술형)에 따라 절차가 갈린다. 아래 각각.
- 전제: 급소 인식(입구)이 작동해야 한다(논리스위치·표지사전 연결됨).

---

## 1. 공통 — 급소 인식 위에 선다
- 입력: 문항 텍스트(+제시문). 
- 급소 인식(v2)이 조사·어미·부사 → 기능표지 → 5색(B·C·P·D·Q) → 급소 K 를 규칙으로 뽑는다.
- 문항 분석은 그 산출을 받아 **계열별 실체로 요약**한다(새로 판단이 아니라 받아서 형식화).
- **출처 인식은 하지 않는다** — 문항 밖 사실이라 규칙으로 안 나오고, 제각각·추측이라 버린다.
  (제시문에서 뽑는 것은 «출처»가 아니라 «핵심».)

---

## 2. 서술형 문항 분석

### 절차
```
문항 → 급소 인식 (5색·K)
  ↓
실체 요약 = (B·D·P 바탕) → (K·Q 도달) 의 관계
  · 바탕: B(개념)·D(정의)·P(상황)  — 문제가 딛는 것
  · 도달: K(급소)·Q(질문)          — 문제가 향하는 것
  ↓
필터 판정 (아래 5. 공통 필터)
```

### 구현 방법
- F2(조각 역산)가 낸 조각에서 «바탕 요소(B·D·P)»와 «도달 요소(K·Q)»를 분류.
- 실체 = 「이 바탕에서 이 급소로 가는 관계」한 줄로 요약(자취용 자연어 + 판정용 구조).
- 계열 분기: 수리=D(정의) 바탕 / 인문사회국어=P(상황) 바탕. (조합 입력에 계열 포함)
- 산출: 실체 요약 → 선생 확인 창의 재료 + 루브릭의 뿌리(같은 조각).

---

## 3. 논술형 문항 분석

논술은 «여러 제시문의 관계」를 읽는다 — 서술형보다 한 층 복잡. 세 단계.

### 3-1. 제시문 각각 → 핵심 (답변처럼 인식)
```
제시문 하나 = 하나의 글(답변처럼 취급)
  ↓ 5색 분해 (B·C·P·D·Q) — 학생 답 채점하는 그 엔진으로
제시문의 급소 = 핵심 (이 제시문이 «무엇을 말하나»)
```
- **출처(어디서 왔나)가 아니라 핵심(무엇을 말하나)**를 뽑는다. 핵심은 텍스트 안 논리라 규칙으로 나온다.
- 구현: 각 제시문을 입구(급소 인식)에 태워 핵심 급소를 추출. (제시문 = 답변 취급)

### 3-2. 제시문 급소 배열 → 사이의 관계
```
제시문 핵심들을 나란히 배열 → 비교 → 관계 설정
  · 유사  — 급소가 같은 방향 (같은 편)
  · 대비  — 급소가 맞섬 (반대 편)
  · 실증  — 한 제시문이 다른 것의 사례·증거 (이론↔사례)
```
- 구현: 제시문 핵심 급소들을 쌍으로 비교, 관계 유형(유사/대비/실증) 판정.
  (급소의 방향·층위 대조 규칙 = 봉인.)

### 3-3. 제시문 관계 ↔ 논제 급소 → 연결점
```
논제(발문) 급소 = 「제시문 관계를 어떻게 다루라」는 것
  · 예: 「(나)(다)에 적용될 윤리 구분」 = (나)(다)↔(가)의 실증 관계를 찾아라
  · 예: 「(라)㉠을 (마)로 비판」 = (라)↔(마)의 대비 관계를 논하라
  ↓
제시문 관계 ↔ 논제 급소 대응 → 연결점
  · 연결점 명확 → 관계가 급소를 받침 (좋은 문항)
  · 연결점 없음/흐림 → 발문-제시문 틈 (악문)
```
- 구현: 논제 급소가 요구하는 «관계 유형」과, 3-2에서 세운 «실제 관계」를 대응.
  일치하면 연결점 성립, 어긋나면 악문 신호(발문이 요구한 관계가 제시문에 없음).

### 논술형 실체 요약
```
실체 = 「(도구 제시문)을 잣대로, (표적 제시문)들의 관계(유사/대비/실증)를
        논제 급소가 요구하는 방식으로 다룬다」
  · 도구: 다른 제시문을 재는 잣대 (이론·비판 기준)
  · 표적: 재어지는 대상 (사례·관점)
```

---

## 4. 서술형 ↔ 논술형 차이 (요약)
| | 서술형 | 논술형 |
|---|---|---|
| 실체 | (B·D·P)→(K·Q) 한 문항 내 요소 관계 | 제시문들 «사이»의 관계 + 논제 연결 |
| 제시문 | 없거나 부차 | 핵심 추출 + 관계 설정이 핵심 |
| 급소 | 문항 논리에서 | 논제 급소 = 제시문 관계를 다루라 |
| 악문 감지 | 조각 겹침·급소 불명·요소 결손 | + 발문-제시문 틈(관계 불일치) |

---

## 5. 공통 필터 판정 (서술형·논술형 공통)
문항 분석의 결과로 «통과/거르기»를 판정한다.
```
· 급소 명확?          — K 중심 조각이 뚜렷한가
· 관계 적절?          — 서술형: 바탕→급소 / 논술형: 제시문 관계↔논제 연결점
· 재료 완결?          — 제시문·발문 다 있는가 (부족하면 조건부·재판정)
· 요소 결손?          — 필요한 조건이 문항에 있는가
· 중의성(조각 겹침)?   — 한 실체가 두 조각에 걸치는가
· 정교화 필요?        — 위에서 삐걱대면 정교화/추가논제 신호
    ↓
통과  → 최종 결정 → 루브릭창
거르기 → 정교화(의도 고도화)/추가논제 → (삼세번) → 재판정
```
- 다경로 표시: 단일정답 아닌 지점(예: 사례의 윤리 귀속이 여러 근거로 성립)을
  «GJ 다경로 채점 적용 지점」으로 미리 표시.

## 6. 선생 확인 창 (교사 자기 검증 UI)

필터 판정 후 교사가 직접 확인하는 단계. 엔진이 판정한 것을 교사가 최종 승인한다.

```
[문항 적절성 체크 화면]

급소(k)       : ○○
실체 요약     : ○○
필터 판정     : 통과 / 거르기
다경로 지점   : ○○ (있는 경우)

─────────────────────────────
교사 확인:
  ① 급소가 내 의도와 맞다       → [통과] 루브릭창으로
  ② 급소는 맞으나 표현 수정     → [수정 입력] → 재판정
  ③ 정교화 필요                → [정교화 모드]
  ④ 추가 논제 필요             → [논제 생성 모드]
─────────────────────────────
```

- 교사가 ①을 선택해야만 루브릭창으로 넘어간다. 엔진 단독으로 넘어가지 않는다.
- ②③④는 정교화·논제생성 명세서(별도)로 연결.
- **교사가 급소를 수정하면 → 수정된 급소로 루브릭 전체 재생성.**

## 7. 모범답안 검증 (F6 위에 얹힘)

> 모범답안이 교사 자신이 설정한 급소에 실제로 닿는지 — 엔진이 확인한다.
> 교사를 신뢰하는 게 아니라, 교사의 의도를 구조로 잡는 것.

### 검증 흐름
```
교사가 모범답안 작성 (또는 기존 모범답안 입력)
    ↓
급소 인식 엔진(입구)으로 역채점
    ↓
모범답안의 급소 도달 여부 판정
    ↓
일치  → 모범답안 확정 → GJ 채점 기준으로 등록
불일치 → "모범답안이 급소 ○○에 닿지 않음" 표시
         → 교사 수정 → 재검증
```

### 검증 기준
- 모범답안이 **조각 전체를 커버**하는가 (빠진 조각 없나)
- 모범답안의 경로가 급소에 **닿는가** (경로가 달라도 급소 도달이면 통과)
- 다경로가 있는 경우 → 모범답안이 **한 경로의 견본**임을 명시

### 성격
- 모범답안은 심판이 아니라 **견본**이다. GJ 채점의 기준은 급소 도달이지 모범답안 일치가 아니다.
- 검증은 모범답안이 견본으로서 급소를 제대로 보여주는지 확인하는 것.

---

## 8. 구현 순서 (전체)

```
문항 입력
    ↓
1. 급소 인식(v2) 산출
2. 서술형/논술형 실체 요약
3. (논술형) 제시문 핵심 추출 → 관계 설정 → 연결점
4. 필터 판정 (통과/거르기 + 다경로 표시)
5. 선생 확인 창 → 교사 승인
    ↓ (통과)
6. 루브릭 생성 (F1~F5)
7. 모범답안 입력 → F6 역채점 검증
    ↓ (확정)
8. GJ 채점 실행
```

- ※ 봉인: 급소 판정·5색 분해·관계 대조 규칙은 봉인 모듈 호출. 코드에 직접 안 씀.
- ※ 실체 분석은 루브릭과 같은 조각에서 나오므로, 루브릭 코어(F1~GJ) 위에 얹는다.
- ※ 논술형 제시문 개수: 구현 시 상한선 설정 필요 (쌍 비교 수 = n(n-1)/2).

---
_핵심: 서술형 = (B·D·P)→(K·Q) / 논술형 = 제시문 핵심 → 관계(유사·대비·실증) → 논제 연결점._
_출처는 버리고 핵심을 취한다. 제시문도 답변처럼 인식 — 같은 급소 엔진 하나로._
_문항 분석 = 1차 필터. 교사 승인 후 루브릭창으로. 모범답안도 급소로 검증한다._
